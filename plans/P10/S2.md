## T4 — Lecture tolérante, et les squelettes passent dans le script

### Objectif
Le script lit tout ce que les squelettes et les gabarits font écrire, avec leurs variantes de
ponctuation, et un test le prouve **en lisant les squelettes eux-mêmes**.

### Pourquoi
C'est la cause de l'incident MYO du 2026-09-22 (vague jamais lancée) et de reprises lancées sur
la mauvaise branche. Sans test sur les squelettes, la prochaine retouche d'un exemple recassera
le contrat en silence.

### Lire / Modifier
Modifier : `plugin/bin/prochaine-action.mjs`, `tests/tester-scripts.mjs`, `tests/fixtures/` (si
une fixture y est plus lisible), `plugin/skills/nouveau-plan/SKILL.md` (ligne du format
d'extension seulement), `plugin/skills/reprendre-echec/SKILL.md` (gabarit l. ~125-195 seulement).

### Étapes
1. En-tête de vague : accepter un `- ` initial facultatif, et une parenthèse facultative entre
   `**` et `:`. Par exemple
   `/^(?:-\s*)?\*\*Vague\s+(\d+)(?:\s*—\s*([^*]+?))?\*\*\s*(?:\([^)]*\)\s*)?:\s*(.+)$/`.
   Membres : retirer **toutes** les parenthèses (`replace(/\([^)]*\)/g, '')`) avant de chercher
   les `S\d+`, au lieu de couper à la première.
2. `Nature :` normalisée avant comparaison :
   - retirer backticks et `*`, passer en minuscules, retirer les accents (NFD) ;
   - `premisse` → `prémisse`, `execution` → `exécution`, `environnement`, `filtre`,
     `interruption` ;
   - absente → `exécution` (défaut documenté) ;
   - **toute autre valeur non vide** → action `question`, source `nature-inconnue`, avec la valeur
     lue dans le motif.
3. `Tentatives :` : lire `reprise\s*=\s*(\d+)` et `enqu[eê]te\s*=\s*(\d+)` **séparément**, quel que
   soit le séparateur.
4. `Auto :` : reconnaître `oui` suivi d'un séparateur quelconque (`·`, `-`, `,`, espace), puis
   `option <m>`. Un `Auto : oui` sans numéro d'option → comme `non`, avec un `avertissement` dans
   la sortie (« Auto : oui sans option — ignoré »).
5. Session d'état `a-lancer` absente de toutes les vagues → après la boucle des vagues, et avant
   de conclure, action `question`, source `session-hors-vague`, avec la liste des sessions.
6. Gabarit de `reprendre-echec` : une seule forme littérale par ligne mécanique, celle que le
   script lit sans tolérance :
   - `Nature : environnement|exécution|prémisse|filtre|interruption` ;
   - `Tentatives : reprise=<n> enquete=<n>` ;
   - `Auto : oui · option <m>` ou `Auto : non` ;
   - la nouvelle ligne `Premisse : refutee · <preuve>` (T5).
   
   Réécrire la définition de `Nature` (l. ~171) : cinq mots, dont `filtre` (filtre de contenu,
   jamais repris à l'identique) et `interruption` (coupure par quota, écrite par l'orchestrateur).
7. `nouveau-plan/SKILL.md` : le format d'extension devient
   `- **Vague <w> — remédiation de S<j> (ajoutée le YYYY-MM-DD)** : S8 · S9.` (tiret initial, date
   dans le gras).
8. Tests, dans `tester-scripts.mjs`, sur un dépôt jetable :
   - (a) extraire le bloc ```` ```md ```` de `squelette-index.md`, l'écrire en
     `plans/P1/index.md`, lancer `--etat` : **chaque** session de la table appartient à une vague ;
   - (b) même chose, avec en plus la ligne d'extension **telle qu'extraite** de
     `nouveau-plan/SKILL.md` et une session S8 dans la table : S8 est dans une vague ;
   - (c) le bloc gabarit de `reprendre-echec/SKILL.md`, rempli avec des valeurs réelles, est lu
     avec la bonne nature, les bonnes tentatives et le bon `Auto` ;
   - (d) ``Nature : `prémisse` `` → `verifier-premisse` ;
   - (e) `reprise=1 · enquete=0` → budget 1 ;
   - (f) une session hors vague → `question`.

### Validation
- **N0 auto (bloque le commit)** : `node plugin/bin/n0.mjs` → vert.
- **Tests** : cas (a) à (f).
- **Anti-raccourci** : des tests (a) et (b) qui recopient le squelette dans une fixture figée.
  Ils doivent **lire les fichiers de la skill à l'exécution**, sinon la prochaine retouche du

## T5 — Nouveaux états : filtre, interruption, prémisse réfutée, rebase, arbre sale, validation acquittée

### Objectif
Le script rend une action juste là où il bouclait ou rendait `pousser` à tort.

### Pourquoi
Incidents couverts :
- ebm-msp, 2026-09-24 : coupure par quota, puis `pousser` sur un arbre sale ;
- boucle `verifier-premisse` après `REFUTEE` ;
- boucle `validation-humaine` après ton « oui ».

### Décision clé
Décision du 2026-09-24, points 7 et 8. Une interruption ne consomme **aucune** reprise. La
relance passe d'abord par `SendMessage` à l'agent coupé, sinon à froid : c'est l'orchestrateur
qui choisit le canal (S4), le script ne rend que l'action.

### Lire / Modifier
Modifier : `plugin/bin/prochaine-action.mjs`, `tests/tester-scripts.mjs`,
`plugin/skills/orchestrer-plan/references/remediation.md` (ligne `REFUTEE`, l. ~27, et table des
natures : ajouter `filtre` et `interruption`, rien d'autre).

### Étapes
1. **Ordre des tests dans `prochaineAction`**, du premier au dernier :
   1. rebase en cours : `git rev-parse --git-path rebase-merge`, puis `rebase-apply` ; si l'un
      existe → `question`, source `rebase` ;
   2. verrou (déjà présent) ;
   3. session en échec de nature `interruption` → action `relancer-interrompue`
      `{ session, modele, ...champAgent }`, **avant** `pousser`, sans toucher au budget ;
   4. `pousser`, **seulement si l'arbre est propre** : fichiers suivis modifiés
      (`git status --porcelain --untracked-files=no`) → `question`, source `arbre-sale`, jamais
      `pousser` ;
   5. le reste, inchangé.
2. Nature `filtre` → `question`, source `filtre` (motif : « filtre de contenu sur S<k> : jamais
   repris à l'identique »).
3. `.echec.md` portant `Premisse : refutee` (casse et accents libres) → la session suit la branche
   `exécution`, jamais `verifier-premisse`.
4. `validation-humaine` : une vague dont le libellé contient `validée` (accents et casse libres)
   est acquittée. L'acquittement implicite par le démarrage de la vague suivante reste valable.
5. Tests, un par point : rebase, interruption + arbre sale → `relancer-interrompue` (pas
   `pousser`), arbre sale sans échec → `question arbre-sale`, `filtre`, `REFUTEE`, `validée`.
6. `remediation.md` :
   - la ligne `REFUTEE` devient : « l'orchestrateur ajoute au `.echec.md` la ligne
     `Premisse : refutee · <preuve>`, committe, rappelle le script, qui traite la session comme
     `exécution` » ;
   - la table des natures gagne `filtre` → question et `interruption` → `relancer-interrompue`,
     hors budget.

### Validation
- **N0 auto** : `node plugin/bin/n0.mjs` → vert.
- **Tests** : six cas ci-dessus.
- **Anti-raccourci** : un test d'interruption dont l'arbre est propre ne prouve pas la priorité
  sur `pousser`. L'arbre doit être **sale**, avec un commit d'avance.

### Message de commit
`feat(prochaine-action): interruption, filtre, prémisse réfutée, rebase et arbre sale, validation acquittée`
Dernière ligne : `Plan: P10/S2/T5`

## T6 — Clôture et escalade économe

### Objectif
- `fini` n'arrive qu'après une clôture réelle : l'action `cloturer`, puis le marqueur `Clos :`.
- Une revue supprimée au tri ne relance plus `relire`.
- La remédiation ne fait qu'une passe Opus par plan.

### Pourquoi
Incident Chords du 2026-09-24 : les revues ont été supprimées avant la fin. Le bloquant de P8/S5
s'est perdu. La remédiation Opus est le poste le plus cher sur un quota Pro (décision, point 6).

### Décision clé
Décision du 2026-09-24, points 4 et 6. La première reprise d'une session en `exécution` tourne
sur **le modèle de l'index**, la deuxième un cran au-dessus. Au plus **une** passe Opus de
remédiation (reprise ou enquête) par plan, décomptée par une ligne d'index
`Remédiation Opus : <n>` que l'orchestrateur incrémente (S4). Au-delà : `question`, source
`budget-opus`.

### Lire / Modifier
Modifier : `plugin/bin/prochaine-action.mjs`, `tests/tester-scripts.mjs`,
`plugin/skills/nouveau-plan/references/squelette-index.md` (commentaire des lignes
`Remédiation Opus :` et `Clos :`, rien d'autre), `plugin/skills/orchestrer-plan/references/remediation.md`
(table d'escalade seulement).

### Étapes
1. `lireIndex` lit deux lignes facultatives, hors table :
   - `Remédiation Opus : <n>` (absente = 0) ;
   - `Clos : YYYY-MM-DD` (absente = plan ouvert).
2. Fin de boucle :
   - plan à `Workflow :` sans `Clos :` → `{ action: 'cloturer' }` ;
   - avec `Clos :` → `fini` ;
   - plan sans `Workflow :` (antérieur à C4) → `fini`, comme aujourd'hui.
3. Présence d'une revue : `existsSync(<S>.revue.md)` **ou** fichier ajouté par un commit
   (`git log --diff-filter=A --format=%H -- plans/<P>/<S>.revue.md` non vide). Le `Bloquant :` se
   lit seulement si le fichier existe encore.
4. `remedier`, branche `exécution` :
   - modèle non-Opus : `reprise=0` → même modèle que l'index ; `reprise=1` → cran au-dessus ;
   - toute action qui rendrait `modele: 'Opus'` (reprise ou enquête, session Opus comprise)
     alors que `Remédiation Opus ≥ 1` → `question budget-opus`.
   
   La branche `environnement` reste inchangée (même modèle). `enqueteTotalPlan` ne change pas
   non plus.
5. Tests :
   - Sonnet `exécution` `reprise=0` → reprise Sonnet ; `reprise=1` → reprise Opus ;
   - **deux échecs successifs** : S3 remédiée en Opus (`Remédiation Opus : 1` dans l'index, son
     `.echec.md` supprimé au PASS), puis S5 en échec qui demanderait Opus → `question budget-opus` ;
   - plan tout fait sans `Clos :` → `cloturer`, avec `Clos :` → `fini` ;
   - revue ajoutée puis supprimée par un commit → pas de `relire`.
6. `squelette-index.md` : un commentaire HTML documente `Remédiation Opus :` (écrite par
   l'orchestrateur) et `Clos :` (écrite par `fin-de-plan.md`). `remediation.md` : la table
   d'escalade dit « 1re reprise même modèle, 2e un cran au-dessus ; une passe Opus par plan ».

### Validation
- **N0 auto** : `node plugin/bin/n0.mjs` → vert.
- **Tests** : cas de l'étape 5.
- **Anti-raccourci** : le test « deux échecs successifs » doit supprimer le `.echec.md` de S3
  **par un commit**, comme au PASS réel. Un fichier qui n'a jamais existé ne prouve pas que le
  décompte survit à sa suppression.

### Message de commit
