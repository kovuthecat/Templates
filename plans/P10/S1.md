## Fait établi (ne pas resonder)
Dans ~20 projets de l'utilisateur, `.git` est un **fichier** (`gitdir: C:/Users/Kovu/.gitdirs/<projet>`).
`git rev-parse --git-common-dir` rend alors `C:/Users/Kovu/.gitdirs/<projet>`, et `dirname` rend
`C:/Users/Kovu/.gitdirs`. Tout ce qui s'appuie sur `racineDepot()` cherche donc sous `.gitdirs/` :
- le verrou ;
- les plans ;
- le manifeste ;
- le journal des modèles (d'où l'orphelin `C:/Users/Kovu/.gitdirs/.claude/journal-modeles.jsonl`).

Les gitdirs n'ont **pas** de `core.worktree`. Les hooks `PreToolUse` s'appliquent aux sous-agents
(sonde du 2026-09-24). `Stop` et `SessionStart` ne s'y appliquent pas.

## T1 — Racine du dépôt juste, même quand `.git` est un fichier

### Objectif
`racineDepot()` (`lib.mjs`) et sa copie dans `prochaine-action.mjs` rendent l'arbre de travail
principal dans les trois cas :
- `.git` est un dossier ;
- `.git` est un fichier (gitdir déplacé) ;
- on est dans un worktree lié.

Si la racine est introuvable, la garde refuse par défaut.

### Pourquoi
C'est la cause des 6 incidents « commit sous verrou » et du `pousser` rendu sous verrou.
Tant qu'elle reste, aucune consigne écrite ne protège une vague parallèle.

### Décision clé
Décision du 2026-09-24, point 1 : `--show-toplevel` ; en worktree lié, sonder `git worktree list` ;
racine introuvable → **refus par défaut** (le hook se comporte comme sous verrou, message explicite).

### Lire / Modifier
Modifier : `plugin/hooks/lib.mjs`, `plugin/bin/prochaine-action.mjs` (fonction `racineDepot`
uniquement), `tests/tester-hooks.mjs`, `tests/tester-scripts.mjs`.

Ceinture : tous les appelants de `racineDepot`. `grep -n racineDepot plugin/` en donne 8 dans
`lib.mjs`, `sessionstart-contexte.mjs`, `postmodelswitch-journal.mjs` et `prochaine-action.mjs`.
Chacun doit tolérer `null` s'il est possible.

### Étapes
1. **Sonde, au premier plan, dans le scratchpad.** Crée un dépôt avec
   `git init --separate-git-dir <tmp>/gd <tmp>/arbre`, fais un commit, puis
   `git -C <tmp>/arbre worktree add <tmp>/lie`. Depuis `<tmp>/lie`, lance
   `git worktree list --porcelain`. Note dans le bilan si la première entrée `worktree <chemin>`
   vaut `<tmp>/arbre`. Ce résultat décide de l'étape 3.
2. `racineDepot(cwd)` :
   - si le cwd n'est pas un worktree lié (`worktreeLie`), rendre
     `git rev-parse --path-format=absolute --show-toplevel` ;
   - sinon, si `basename(--git-common-dir) === '.git'`, rendre `dirname(common)` (cas classique
     inchangé).
3. Worktree lié d'un gitdir déplacé :
   - si la sonde l'a montré fiable, prendre la première entrée `worktree` de
     `git worktree list --porcelain`, et l'accepter seulement si le `.git` de ce chemin (fichier
     ou dossier) désigne bien ce `common-dir` ;
   - sinon, rendre `null`.
4. `vagueParallele(cwd)` rend `true` quand la racine est `null` : c'est le refus par défaut.
   Ajouter `racineIntrouvable(cwd)`. `pretooluse-git.mjs` s'en sert pour dire, dans son message de
   refus : « racine du dépôt introuvable (worktree lié d'un dépôt à `.git` déplacé) : committe
   depuis l'arbre principal ».

   Les autres appelants (`sessionsOuvertes`, `revuesManquantes`, journal, manifeste) rendent
   « rien à signaler » sur `null`. Ils ne plantent jamais : un hook qui lève une exception coupe
   la session.
5. Même logique dans `prochaine-action.mjs` (`racineDepot` l. ~71), sans importer `lib.mjs`.
   `bin/` est vendoré sans `hooks/` : il faut donc copier la fonction, avec un commentaire qui
   renvoie à `lib.mjs`. Si la racine est `null`, `waveLock` vaut `true`.
6. Tests `tester-hooks.mjs`, sur un dépôt en gitfile (`git init --separate-git-dir`) :
   - (a) verrou présent → `pretooluse-git` refuse `git commit -m x` ;
   - (b) sans verrou → il laisse passer ;
   - (c) dans un worktree lié de ce dépôt, avec verrou dans l'arbre principal → refus ;
   - (d) `postmodelswitch-journal` écrit sous `<arbre>/.claude/`, jamais à côté du gitdir.

   Test `tester-scripts.mjs` : dépôt en gitfile, verrou présent, un commit d'avance. L'action ne
   doit **pas** être `pousser`.

### Validation
- **N0 auto (bloque le commit)** : `node plugin/bin/n0.mjs` → quatre commandes vertes.
- **Tests** : les cas (a) à (d) et le cas `pousser` ci-dessus.
- **N1 visuel auto** : —
- **N2 humain** : —
- **Anti-raccourci** : un test en gitfile qui passe parce que `wave.lock` a été créé **à côté du
  gitdir** et non dans l'arbre. Le verrou du test doit être à `<arbre>/.claude/wave.lock`, et le
  cas (b) prouve que le refus vient bien de lui.

### Si bloqué
Aucun des quatre critères n'est en jeu. Si la sonde de l'étape 1 est ambiguë, applique le refus
par défaut, c'est la décision.

### Message de commit (appliqué par la session elle-même)
`fix(hooks): racine du dépôt juste quand .git est un fichier, refus par défaut sinon`
Dernière ligne du commit, obligatoire : `Plan: P10/S1/T1`

## T2 — Cache C4, commandes `git -C`, revues des sessions `low`, plafond `.echec.md`

### Objectif
Quatre trous annexes de la garde, tous dans `plugin/hooks/`.

### Pourquoi
- Une fois la racine corrigée, `<racine>/.git` est un fichier, et le cache C4
  (`lib.mjs` l. ~340) ne s'écrit plus. Le hook relancerait alors `git ls-remote` à chaque
  démarrage.
- `git -C <dir> commit` passe sous la regex.
- Le hook `Stop` réclame une revue pour une session `low`, que personne ne relira (C7).
- Le plafond `.echec.md` n'est posé que comme donnée.

### Lire / Modifier
Modifier : `plugin/hooks/lib.mjs`, `plugin/hooks/pretooluse-git.mjs`, `tests/tester-hooks.mjs`.

### Étapes
1. Cache C4 : chemin =
   `git rev-parse --path-format=absolute --git-path workflow-version.json`. Le test du cache
   (l. ~469) tourne aussi en gitfile.
2. `pretooluse-git.mjs` : accepter les options globales avant la sous-commande, pour le refus sous
   verrou comme pour le refus de `add -A`/`.`/`--all` et de `commit -a`. Par exemple
   `/\bgit(\s+-(?:C|c)\s+\S+)*\s+(commit|push)\b/`, et l'équivalent pour `add`. Tests :
   `git -C . commit -m x` et `git -c user.name=x commit -m x` refusés sous verrou.
3. `revuesManquantes` : ne pas réclamer la revue d'une session dont l'Effort, lu dans l'index,
   vaut `low`. Réutilise la lecture de table existante (`sessionsOuvertes` ou son parseur).
   Test : une session `low` qui committe du code → aucune revue réclamée.
4. `depassements()` : appliquer le plafond `plans/<P>/S<k>.echec.md` de `plafonds.json` à chaque
   fichier qui correspond au motif. Aujourd'hui seuls les chemins fixes sont comparés. Test : un
   `.echec.md` de 41 lignes est signalé.

### Validation
- **N0 auto** : `node plugin/bin/n0.mjs` → vert.
- **Tests** : les quatre cas ci-dessus.
- **Anti-raccourci** : ne pas contourner le cache C4 en le désactivant. Le test doit prouver que
  le fichier est bien **écrit** en gitfile, et relu au second appel.

### Message de commit
`fix(hooks): cache C4 sous le gitdir, git -C refusé sous verrou, revues low exemptées, plafond .echec.md`
Dernière ligne : `Plan: P10/S1/T2`

## T3 — Collecteur d'incidents, version chargée du dépôt source, renvois des hooks

### Objectif
Trois points :
- le collecteur lit les champs regroupés sur une même puce ;
- dans le dépôt source, `SessionStart` signale un plugin local plus ancien que la source ;
- les commentaires et renvois périmés des hooks sont corrigés.

### Pourquoi
Le gabarit §9b met trois champs par puce, séparés par `·`, alors que `collecter-incidents.mjs`
(l. ~61) n'en lit qu'un par ligne : 9 alertes ⚠ sur 11 sont fausses. Le 2026-09-22, le plugin
local n'était pas chargé sans que rien ne le dise (incidents Templates du 2026-09-23 et
DrumsTraining du 2026-09-24).

### Lire / Modifier

`plugin/hooks/lib.mjs` (commentaire l. ~207), `plugin/hooks/stop-contexte.mjs` (message l. ~79),
`plugin/hooks/hooks.json` (`_comment`), `tests/tester-hooks.mjs`, `tests/tester-scripts.mjs` si le
collecteur y est testé.

### Étapes
1. Collecteur : pour chaque puce `- …`, découper sur `·`, puis lire chaque segment `Champ : valeur`.
   Vérification : `node plugin/bin/collecter-incidents.mjs` ne doit plus marquer ⚠ que les deux
   vrais écarts (MYO `2026-09-22-vague-ajoutee-non-reconnue`, Templates `2026-09-17-classificateur-…`).
2. `SessionStart`, **dépôt source seulement** (pas de `.claude/workflow/manifest.json`, et

3. Renvois :
   - `stop-contexte.mjs` cite « `/orchestrer-plan` Étape 5 » : l'étape de relecture est désormais
