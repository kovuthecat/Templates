## T9 — `/orchestrer-plan` : l'orchestrateur est le seul rédacteur de ce qui suit une session

### Objectif
La table des actions de `/orchestrer-plan` couvre tout ce que le script peut rendre. Pour chaque
action, elle dit qui écrit quoi, et quel commit s'ensuit.

### Pourquoi
La décision nomme un seul auteur par geste. Sans ce texte, les nouvelles actions de S2 (`cloturer`,
`relancer-interrompue`, les nouvelles sources de `question`) tomberaient dans « action inconnue ».

### Lire / Modifier
Modifier : `plugin/skills/orchestrer-plan/SKILL.md`, `plugin/skills/orchestrer-plan/references/remediation.md`.

### Étapes
1. **Prompt de lancement** (l. ~108-119) : garder la ligne d'invariant `EXECUTANT.md` (session).
   Ajouter deux lignes :
   - « `.claude/wave.lock` présent → ni commit ni push » ;
   - « Mode orchestré : `/fin-de-tache`, section Mode orchestré ; ta dernière ligne est
     `VERDICT:` ».
   
   Conserver `run_in_background` et l'interdit de travail de fond.
2. **Collecte** : si le retour d'une session n'a pas de `VERDICT:` **et** correspond à
   `/session limit|rate.?limit|\b429\b|terminated early/i`, l'orchestrateur écrit
   `plans/P<n>/S<k>.echec.md` :
   - `Nature : interruption` ;
   - `Tentatives :` recopiées si le fichier existait, sinon `reprise=0 enquete=0` ;
   - `Blocage : coupure par quota pendant <T<m> si connu>` ;
   - une ligne `Agent : <identifiant rendu par l'appel Agent>`.
   
   Il committe **ce seul fichier**, sans toucher au travail partiel de l'arbre, puis rappelle le
   script. Garder l'identifiant de chaque appel `Agent` dès le lancement (c'est déjà le canal court).
3. **Action `relancer-interrompue`** :
   - attendre la réinitialisation du quota. Le dire à l'utilisateur en une ligne, avec l'heure si
     le message la donne ;
   - puis `SendMessage` à l'identifiant de la ligne `Agent :`, message « Quota revenu. Reprends
     où tu t'es arrêtée ; l'arbre contient ton travail partiel. Fin : `/fin-de-tache` Mode
     orchestré, dernière ligne `VERDICT:`. » ;
   - **exception écrite aux trois conditions du canal court** (§9c) : N0 peut être rouge en
     pleine édition ;
   - `SendMessage` en échec → reprise **à froid** sur le même modèle, par le prompt de
     `remediation.md`, avec le `.echec.md` en entrée ;
   - dans les deux cas, **aucune** reprise décomptée ;
   - au `PASS`, supprimer le `.echec.md` par un commit.
4. **Action `relire`** (Étape 2) :
   - retirer la ligne d'invariant `EXECUTANT.md` du prompt du relecteur (S3 l'a rendue facultative) ;
   - une fois la ligne rendue lue, l'orchestrateur **committe** chaque `.revue.md` déposé et, si
     `Bloquant ≥ 1`, passe le statut de la session à `[x]!` dans l'index ;
   - message `revue(P<n>): S<k> relue, <n> bloquant(s)`, repère `Plan: P<n>/S<k>` ;
   - « Sans verrou, rien à réécrire » (l. ~135) disparaît.
5. **Action `cloturer`** : l'orchestrateur déroule `fin-de-tache/references/fin-de-plan.md`
   lui-même, puis rappelle le script, qui rend `fini`.
6. **Action `validation-humaine`** :
   - après le « oui » de l'utilisateur, ajouter `· validée` au libellé de la ligne de vague
     (`- **Vague <w> — validation-humaine · validée** : …`) ;
   - committer, pousser, rappeler le script.
7. **Remédiation Opus** : à chaque `reprendre` ou `enqueter` rendu avec `modele: Opus`,
   incrémenter la ligne d'index `Remédiation Opus : <n>` (la créer à 1 sous l'objectif si elle
   manque), dans le même commit que le lancement ou juste avant.
8. **Table des sources de `question`** (l. ~198) :
   - compléter avec `effort-invalide`, `session-hors-vague`, `nature-inconnue`, `filtre`, `rebase`,
     `arbre-sale`, `budget-opus` ;
   - corriger `motifs.source` en `options.source` ;
   - action ou source **inconnue** → `question` à option unique (« mettre à jour le workflow »),
     plus un incident §9b. Supprimer « correctif localisé si possible… sinon FAIL prémisse »
     (l. ~51-52).
9. **Conflit de rebase** (l. ~46) : « `git rebase --abort`, puis rappeler le script » (il rend
   `question rebase` si l'abandon échoue).
10. **Boucle en vague parallèle** (l. ~19) : « rappeler le script **après la fin de vague**, pas
    entre deux notifications de sessions ».
11. **l. ~174** : supprimer « push groupé sur `main` en dernier geste… jamais depuis une session »,
    et renvoyer à l'action `pousser` (C3).
12. **Modèle de l'orchestrateur** : une ligne en tête, « L'orchestrateur tourne en Sonnet · medium.
    Si tu tournes en Opus, dis-le à l'utilisateur au premier tour : il paie Opus pour exécuter un
    script. »
13. `remediation.md`, message `SendMessage` (l. ~41-47) : ajouter les lignes du prompt à froid
    (l. ~69-72) :
    - pas de travail de fond ;
    - incrémente `Tentatives :` ;
    - réécris ton `.echec.md` si tu échoues ;
    - dernière ligne `VERDICT:`.
    
    Retirer la ligne `EXECUTANT.md` du prompt `verificateur-premisse`. Supprimer la variante
    « bloquant de revue » du prompt de reprise (l. ~67), puisque la promesse C5 est retirée.

## T10 — `fin-de-plan.md` : clôture par l'orchestrateur, marqueur `Clos :`

### Objectif
La clôture trie les revues **déjà commitées**, verse les `[x]!` dans `TASKS.md`, puis supprime les
revues. Elle pose `Clos : YYYY-MM-DD` dans l'index, et pousse.

### Lire / Modifier
Modifier : `plugin/skills/fin-de-tache/references/fin-de-plan.md`.

### Étapes
1. En tête : « Déroulée par l'orchestrateur sur l'action `cloturer` (mode orchestré), ou par la
   dernière session en chaînage manuel. Jamais par une session lancée par l'orchestrateur. »
2. Ordre :
   1. vérifier que chaque `.revue.md` est commité (`git ls-files`), et le committer s'il ne l'est
      pas ;
   2. trier : verser chaque bloquant dans `TASKS.md` et passer son `[x]!` à `[x]` ;
   3. supprimer les `.revue.md` dans un commit ;
   4. écrire `Clos : YYYY-MM-DD` sous l'objectif de l'index ;
   5. faire la même chose pour `STATUS.md` et `VALIDATION.md` ;
   6. pousser.
3. L. ~29 (push cloud) : renvoyer à `WORKFLOW.md` §4b, sans dupliquer la règle.
4. 8b : `claude plugin update workflow@templates --scope local` (le vérifier).

### Validation
- **N0 auto** : `node plugin/bin/n0.mjs` → vert.
- **Anti-raccourci** : un ordre où la suppression précède le versement. C'est l'incident Chords.

### Message de commit

### Objectif

### Pourquoi

suite du plan doit tourner sur un orchestrateur qui connaît les actions de S2 (validation humaine

### Lire / Modifier
Modifier : `plugin/.claude-plugin/plugin.json`, `CHANGELOG.md`, `plugin/MIGRATION.md` (si le fichier
tient une section par version).

### Étapes
1. `plugin.json` : `"version": "0.45.0"`.
2. `CHANGELOG.md` : une entrée datée en tête, sur le modèle de 0.44.0. Ce que ça change pour un
   projet :
   - le verrou refuse de nouveau les commits, `.git` déplacé compris ;
   - une session orchestrée finit toujours par `VERDICT:` ;
   - l'orchestrateur committe les revues et clôt le plan ;
   - une coupure par quota se relance ;
   - une passe Opus de remédiation par plan ;
   - le relecteur passe une fois ;
   - la promesse de reprise automatique d'un bloquant est retirée.
   
   Citer la décision du 2026-09-24.
3. `MIGRATION.md` : rien à faire au-delà de `/maj-workflow`. Signaler qu'un plan en cours sans
   `Clos :` recevra l'action `cloturer` à sa fin.
4. N0, commit, puis au premier plan :
   - `node plugin/bin/publier.mjs` ;
   - `claude plugin update workflow@templates --scope local` ;
   - `claude plugin list` → `workflow@templates` en **0.45.0**, `✔ enabled`.

- **N0 auto** : `node plugin/bin/n0.mjs` → quatre `PASS`.
- **Anti-raccourci** : `publier.mjs --dry-run` ne publie rien. Le bilan porte la sortie du
