## T5 — `--lever-bloquant S<k> <décision>` : un bloquant mécanique se lève, tracé

### Objectif
Nouveau geste du moteur `--lever-bloquant S<k> <docs/decisions/…>` : il lève le bloquant de revue d'une
session faite quand une décision écrite le justifie (le cas d'origine : `n0.json` modifié hors zone),
l'écrit dans la revue de la session avec le chemin de la décision, et committe le tout. La question
`dependance-revue` propose ce geste en option, avec la commande exacte.

### Pourquoi
laser-tools (2026-11-16) : la question `dependance-revue` proposait de « réviser la dépendance » sans
aucun geste pour le faire ; le plan P5 est resté arrêté. Un bloquant qu'une décision a déjà tranché doit
pouvoir se lever sans éditer les fichiers à la main, et laisser une trace qu'on retrouve.

### Décision clé
- L11. Le geste refuse (sortie non nulle, message) si le chemin de décision n'existe pas ou n'est pas
  sous `docs/decisions/`, ou si la session n'a pas de bloquant. Jamais de levée sans décision écrite.
- Commit par le mécanisme d'écriture existant du moteur, message `revue(P<n>/S<k>): bloquant levé — <décision>`
  avec la ligne de repère du moteur.
- Après le geste, le moteur relancé ne rend plus `dependance-revue` pour les sessions que ce bloquant retenait.

### Lire / Modifier
- Incident ou index d'un autre projet (lecture) : C:/Users/Kovu/Projets/laser-tools/docs/workflow/incidents/2026-11-16-revision-dependance-introuvable.md
- Lire : `plugin/agents/relecteur-session.md` — forme d'une revue (bloquants, ligne dépendances).
- Lire : `plugin/skills/orchestrer-plan/SKILL.md` — comment une option de question devient un geste.
- Modifier : `plugin/bin/prochaine-action.mjs`
- Modifier : `plugin/skills/orchestrer-plan/SKILL.md`

- Modifier : `tests/fixtures/plans/` (créer les fixtures nécessaires)

### Étapes
1. Repérer comment une revue « libère » ses dépendants aujourd'hui (`dep.revue.dependances !== 'libres'`,
   l.~1486) : le geste écrit cette même marque, plus une ligne qui cite la décision — réutiliser la
   marque existante plutôt qu'en inventer une.
2. Ajouter l'option `--lever-bloquant` (deux valeurs, `valeursOption`), contrôles de la Décision clé,
   écriture, commit.
3. Texte de la question `dependance-revue` : l'option « Réviser… » devient « Lever le bloquant de <S>
   si une décision le justifie : `node <chemin>/prochaine-action.mjs P<n> --lever-bloquant <S> <docs/decisions/…>` ».
4. `orchestrer-plan/SKILL.md` : une ligne, là où sont listés les gestes de l'orchestrateur sur réponse
   de l'utilisateur — il lance ce geste quand l'utilisateur choisit cette option et donne la décision.
5. Tests : levée acceptée (revue modifiée, commit présent, plus de `dependance-revue`) ; refus sans
