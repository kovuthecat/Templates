## T4 — MIGRATION.md : checklist déclarative de mise à niveau d'un projet

### Objectif

Un fichier autoportant qu'une session Sonnet `medium`, lancée dans n'importe quel projet existant
(contexte hétérogène), peut dérouler seule pour l'amener à l'état cible sans perdre de contenu.

### Décision clé

D4 (index) : la migration est du **jugement**, pas un script — MIGRATION.md décrit l'état cible
et la méthode de classement, pas des commandes à exécuter aveuglément. Priorité absolue :
ne jamais perdre de contenu spécifique au projet.

### Lire / Modifier

- Créer : `MIGRATION.md`

### Étapes

1. Rédiger MIGRATION.md avec cette structure (contenu à développer, structure imposée) :
   - **§But & état cible** — tableau des fichiers attendus dans un projet migré : copiés
     (liste du README), stub AGENTS.md, import CLAUDE-BASE dans CLAUDE.md, PAS de
     `.claude/skills/fin-de-tache` local, PAS de copie de WORKFLOW/CONVENTIONS.
   - **§Étape 0 — Inventaire** : localiser les fichiers de contexte réels du projet sans
     préjugé d'emplacement. Variantes connues à chercher : racine, `fichierscontexte/`,
     `CONTEXTE/<x>-context/`, `SPEC.md`, `ROADMAP.md`, `PLAN_*.md`, ancien format
     `plans/PLAN_<id>.md` et `T<n>.md`, `PROJECT_BRIEF`/`DECISIONS` sous d'autres noms.
   - **§Étape 1 — Classer** chaque fichier trouvé : **générique** (copie d'un ancien template,
     même remaniée) / **spécifique** (contenu produit du projet) / **mixte**.
   - **§Étape 2 — Appliquer** : générique → supprimer (le central le remplace) ; mixte →
     extraire le spécifique vers le fichier cible standard, puis supprimer le reste ;
     spécifique → conserver tel quel (ne déplacer vers un nom standard que si trivial et sans
     casser de renvois existants).
   - **§Étape 3 — CLAUDE.md & skill** : reconstruire CLAUDE.md sur le squelette actuel en
     conservant les commandes réelles et règles spécifiques ; ajouter l'import CLAUDE-BASE ;
     écrire le stub AGENTS.md ; **supprimer `.claude/skills/fin-de-tache` local** (il masquerait
     la skill utilisateur).
   - **§Garde-fous** : en cas de doute sur un contenu → le conserver et le signaler, jamais le
     supprimer ; pas de refonte du contenu produit (brief, décisions) à l'occasion de la
     migration ; staging explicite ; un commit unique
     `chore: migrate context files to central templates` ; rapport final des écarts non résolus
     rendu à l'humain en fin de session.
   - **§Annexe — Cas particuliers par projet** : initialisée avec les cas connus
     (app-rectte-course-md : `fichierscontexte/` + règle « mise à jour avant chaque commit » à
     préserver ; FermentLab : `CONTEXTE/fermentlab-context/` ; Chords : `vercel.json`
     INTOUCHABLE ; laser-tools : SPEC.md à lire avant modif). Enrichie après chaque migration.
2. Relire : le fichier doit être compréhensible par un Sonnet `medium` qui n'a AUCUN autre
   contexte que le projet dans lequel il tourne.
