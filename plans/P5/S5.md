## T14 — `plugin/agents/critique-plan.md`

### Objectif
L'agent critique : frontmatter, contrat d'entrée, cinq questions, format de sortie, interdits, et
la sonde `effort:`.

### Pourquoi
D3 : `verificateur-plan` exclut la conception ; l'approbation humaine du plan a lieu avant lui. Un
plan mécaniquement cohérent peut garder une hypothèse fragile ou une récupération non définie. Une
critique **ciblée**, avant l'approbation, est le seul moment où elle pèse sur l'arbitrage.

### Décision clé
Décision (e). Frontmatter :

```yaml
---
name: critique-plan
description: Confronts a plan's design to the repository before the user approves it — the scenario that defeats the goal despite green tests, the implicit responsibility, state after interruption or retry, criteria that miss invariants, a much simpler solution. Use once, from /nouveau-plan end of step 1, on architectural plans or named triggers only. Never rewrites the plan, never judges product scope. Returns PASS or numbered findings with target and minimal fix, then the list of unresolved choices.
tools: Read, Grep, Glob
model: opus
effort: high
maxTurns: 25
---
```

Corps, dans l'ordre des agents existants :
- **Ce que tu reçois** : le chemin de la décision applicable ; la synthèse d'Étape 1 recopiée dans
  le prompt (flux, hypothèses typées, découpage envisagé, critères de réussite) ; jamais la
  conversation. Tu **lis le dépôt** pour vérifier chaque affirmation qui s'y confronte.
- **Les cinq questions**, et seulement les angles que ce plan touche : quel scénario concret ferait
  échouer l'objectif malgré des tests unitaires verts ; quelle responsabilité ou dépendance reste
  implicite ; que deviennent l'état et les effets après interruption, échec partiel ou appel répété ;
  les critères mesurent-ils le comportement utile, invariants compris ; une solution nettement plus
  simple satisfait-elle déjà les contraintes.
- **Ce que tu ne fais pas** : aucune écriture ; aucune recommandation de périmètre produit ; aucune
  remarque de style ou de formulation ; tu ne rediscutes pas une décision citée par le plan —
  tu peux dire qu'un **fait** la contredit, avec la preuve ; un constat sans cible **et** sans
  correction ne s'écrit pas ; `PASS` explicite quand il n'y a rien — un verdict propre est valide.
- **Ce que tu rends** :

```
CRITIQUE: PASS
Choix non résolus : aucun
```
ou
```
CRITIQUE: 2 constat(s)
1. DÉFAUT · S2/T5 « Étapes » — <preuve : fichier:ligne ou fait vérifié> → <conséquence sur l'objectif> → <correction minimale>
2. À VÉRIFIER · index « Objectif » — <ce qui manque pour trancher> → <conséquence si faux> → <recherche ou sonde qui tranche>
Choix non résolus : <un choix entre options légitimes que le plan n'a pas reçu, ou « aucun »>
```

`DÉFAUT` = démontré par le dépôt ou par un scénario concret ; `À VÉRIFIER` = plausible, non
démontré. Pas de troisième niveau.

### Référence
`plugin/agents/verificateur-premisse.md` — la section « Pourquoi ce poste existe », la forme des
exemples de sortie, la règle « le doute va à … » : imiter la densité.

### Lire / Modifier

### Étapes
1. Écrire l'agent (≤ 70 lignes).

   dépôt, lancer l'agent une fois sur une entrée triviale (« Critique ce plan : `plans/P4/` — décision

## T15 — `plugin/agents/analyste-flux.md`

### Objectif
L'agent qui lit un flux : frontmatter, méthode en trois pas, sortie à sections fixes, interdits.

### Pourquoi
D2 : `explorateur` rend des chemins et des rôles en vingt lignes ; `/nouveau-plan` Étape 1 demande
un flux complet. Le cadreur reconstruit le fonctionnement depuis une carte de fichiers, ou lit
lui-même — dans le contexte le plus cher. Un agent n'a qu'un modèle : la localisation reste sur
Haiku, la lecture d'un flux passe sur Sonnet (HumanLayer sépare les deux pour la même raison).

### Décision clé
Décision (f). Frontmatter :

```yaml
---
name: analyste-flux
description: Traces how one flow works in the repository — entry, transformations, state, output, errors, consumers — with a file:line reference for every fact, and keeps facts, inferences and unknowns apart. Use when a plan or a framing needs to understand a behaviour, not just locate files (that is explorateur). Read-only, documents what IS; never recommends, never flags bugs.
tools: Read, Grep, Glob
model: sonnet
maxTurns: 25
---
```

Méthode (codebase-analyzer) : points d'entrée et surface → suivre les appels en notant chaque
transformation → documenter la logique clé **sans l'évaluer**. Sortie, sections fixes et dans cet
ordre :

```
Question : <telle que posée>
Révision / zone : <commit ou état + fichiers pertinents>
Faits observés : <affirmation — fichier:ligne>, une par ligne
Flux : <départ → transformation → effet → contrôle>
Inférences : <hypothèse — fondement — ce qui manque pour la vérifier>
Inconnues : <non inspecté | non observable statiquement (appel dynamique, config externe, runtime)>
Couverture : <cherché ; exclu>
```

Interdits : deviner ; recommander ; qualifier un bug ou une qualité ; promouvoir une inférence en
fait ; coller du contenu brut. « Observé statiquement » n'est pas « reproduit à l'exécution » — le
dire. Budget indicatif 600–900 tokens ; une réponse qui ne tient pas dit **ce qui manque** au lieu
de compresser l'inconnu.

### Référence
`plugin/agents/explorateur.md` — la règle 3 (« Si tu ne trouves pas… dis-le ») : même honnêteté,
mais ici étendue à trois catégories (fait, inférence, inconnue).

### Lire / Modifier

### Étapes
