## T5 — Installer le mod dans le plugin de la branche

### Objectif
Mettre le module de S2 dans le plugin de la branche, le réinstaller, et prouver par le cache qu'une
conversation neuve le chargera.

### Pourquoi
Un mod ne se charge qu'au démarrage d'une conversation : la tâche de T6 ouvrira une conversation
neuve, qui doit le trouver dans le cache du plugin.

### Décision clé
- **Condition, premier geste** : Bilan de S2 « Non construit » → T5 et T6 sans objet ; écrire
  `## C2` « non jouée : <motif de S2> » dans les relevés, passer directement à T7 (qui vérifie et
  commite).
- **Contrôle de départ** : comme S1 (T1, Décision clé) — l'orchestration en Sonnet · medium, sinon
  `FAIL` environnement.
- `plugin/hooks/hooks.json` : ajouter `"modules": ["./reglage.ts"]`, sans toucher aux entrées
  existantes. Le module se copie dans `plugin/hooks/reglage.ts`. `plugin/.claude-plugin/plugin.json`
  ne change que si `validate` l'exige — l'exécutant l'ajoute alors au périmètre et le signale.
- Réinstallation : `"$CLAUDE_CODE_EXECPATH" plugin uninstall workflow@templates --scope local`, puis
  `"$CLAUDE_CODE_EXECPATH" plugin install workflow@templates --scope local`. **Pas le shim
  `claude`** (introuvable sur ce poste le 2026-10-06) et **pas `update`** : à version égale, il ne
  recopie rien (P13/S5).

### Lire / Modifier
- Lire : `preuves/mods/reglage/hooks/reglage.ts`
- Modifier : `plugin/hooks/hooks.json`
- Modifier : `plugin/hooks/reglage.ts` (créer)

### Étapes
1. Condition et contrôle de départ (Décision clé).
2. Copier le module, ajouter `"modules"`.
3. `"$CLAUDE_CODE_EXECPATH" plugin validate plugin/.claude-plugin/plugin.json` → `✔` ;
   `node tests/tester-hooks.mjs` → vert.
4. Commit, push, puis réinstallation (Décision clé), les commandes à la suite.
5. Contrôle du cache `~/.claude/plugins/cache/templates/workflow/<version de plugin.json>/` :
   `hooks/hooks.json` porte `"modules"`, `hooks/reglage.ts` est présent ;
   `"$CLAUDE_CODE_EXECPATH" plugin list` montre `workflow@templates` au scope `local`.

### Validation
- **N0 auto (bloque le commit)** : `"$CLAUDE_CODE_EXECPATH" plugin validate plugin/.claude-plugin/plugin.json`
  → `✔` ; `node tests/tester-hooks.mjs` → vert ; après réinstallation, les contrôles de cache de
  l'étape 5.
- **Tests** : — (les tests du module sont en S2)
- **N1 visuel auto** : —
- **N2 humain** : —
- **Anti-raccourci** : la commande d'installation répond « installé » mais le cache ne contient pas
  le module (P12, M1) : seul le contrôle **du cache** prouve l'installation.

### Si bloqué
L'installation échoue après la désinstallation : le poste est sans plugin. Réessayer une fois ;
sinon passer directement à T7 (retrait, réinstallation depuis l'état de `main`), puis `FAIL` nature
`environnement`. Ne jamais laisser le poste sans plugin.
