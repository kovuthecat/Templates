## T4 — Mod de réglage du fil principal, et ses tests simulés

### Objectif
Écrire un mod qui, sur chaque requête du **fil principal** d'une session ouverte par
`Ouvre plans/P<n>/S<k>.md et exécute-le.`, réécrit modèle et effort d'après la ligne `S<k>` de
`plans/P<n>/index.md` ; le prouver par `plugin test`, sans l'installer.

### Pourquoi
Si le lanceur de tâches ignore le frontmatter (B), c'est la seule voie à un seul démarrage payé qui
reste avant le repli A (deux démarrages). Il couvrirait aussi les sessions ouvertes par pastille.

### Décision clé
- **Condition, premier geste** : lire `**Verdict B :**` dans les relevés.
  - `positive` → rien à construire : Bilan « non construit : B positive », commit du Bilan seul,
    `VERDICT: PASS`.
  - `partielle (axe manquant : X)` → construire le mod entier (il réécrit les deux axes, sans
    dommage) ; le Bilan note que seul l'axe X sera jugé en C2.
  - Un axe « non conclu : instrument » ne compte pas comme manquant (index, Conditions). Si c'est
    le seul axe non positif → rien à construire, comme `positive`, motif écrit.
  - `négative` ou `non conclu` (fixture, refus, budget) → construire.
- **Mécanique de l'API** : charger la skill `plugin-authoring` avant d'écrire le module ; elle porte
  l'API des mods. `turn.step` se déclenche avant chaque requête ; `next({ ...e, model })` /
  `next({ ...e, effort })` envoient la requête autrement ; `$.session.messages()` lit la
  conversation (décision, fait relevé dans `claude-code.d.ts`). Ce qui diffère dans la version du
  moteur (`"$CLAUDE_CODE_EXECPATH"`, 2.1.286) se note au Bilan, avec la ligne de type.
- **Reprise d'O1, pas une réécriture** : le parseur d'index vient de
  `git show origin/preuve/mods-2:preuves/mods/orchestration/hooks/orchestration.ts` (fonctions
  `modeleDeIndex`, `cellules`, `lireTexte`, `racine`) — colonne trouvée **par son en-tête**. L'étendre
  à la colonne `Effort` (valeurs `low|medium|high|xhigh|max`) ; même forme de valeur de modèle
  qu'O1 (`sonnet|opus|haiku`).
- **Déclencheur exact** : premier message `user` de la session, texte rogné, égal à
  `^Ouvre plans/(P\d+)/(S\d+)\.md et exécute-le\.$`. Rien d'autre ne déclenche.
- **Jamais un refus** : toute lecture qui échoue → `next(e)` inchangé.
- **Journal** : une ligne JSON par réécriture dans `~/.claude/preuves/mods/reglage.jsonl`
  (`ts`, plan, session, `avant: {model, effort}`, `apres: {model, effort}`) — S3 le lit.

### Référence
`git show origin/preuve/mods-2:preuves/mods/orchestration/tests/orchestration.test.ts` et
`…/tests/fixture-index.ts` : le « monde simulé » (fichiers en mémoire, racine, HOME) et la façon
d'asserter **ce que le moteur reçoit** de `next`. Imiter, en remplaçant `agent.spawn` par
`turn.step`.

### Étapes
1. Condition (Décision clé).
2. Charger `plugin-authoring` ; lire O1 et ses tests par `git show` (Référence).
3. Écrire le module, son `hooks.json` (`"modules": ["./reglage.ts"]`) et son `plugin.json`
   (nom `reglage`, sans `userConfig` sauf exigence de `validate`).
4. Tests : un cas par ligne du tableau de la décision, plus « deux requêtes successives, toutes deux
   réécrites » :

   | Cas | Attendu |
   | --- | --- |
   | premier message conforme, index lisible | modèle et effort réécrits à chaque requête |
   | premier message différent (conversation interactive, `/orchestrer-plan P14`) | inchangé |
   | requête de sous-agent (`agentId` présent) | inchangé |
   | index illisible, ligne absente, valeur inconnue | inchangé, jamais un refus |
   | la cible concorde déjà avec la requête | inchangé, aucune ligne de journal |

   La fixture d'index contient une ligne `Opus | low` **et** une ligne `Sonnet | medium` : la requête
   simulée part en Sonnet · medium, sinon le premier cas passerait sans réécriture.
5. `"$CLAUDE_CODE_EXECPATH" plugin validate preuves/mods/reglage/.claude-plugin/plugin.json` → `✔` ;
   `"$CLAUDE_CODE_EXECPATH" plugin test preuves/mods/reglage` → tout vert.
