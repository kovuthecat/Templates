## T9 — Panneau « fichiers » : l'état git du projet

### Objectif
Un panneau `fichiers` qui liste, groupés par dossier, les fichiers ayant un état git : `●` modifié,
`+` nouveau (non suivi ou ajouté), `↑` commité mais non poussé ; rafraîchi après chaque écriture.

### Pourquoi
Voir d'un coup d'œil ce qui reste à committer ou à pousser, y compris depuis le téléphone, sans
demander de `git status` à Claude.

### Décision clé
- **Seuls les fichiers ayant un état** (consigne du chantier : « fichiers = état git ») ; pas
  d'arborescence complète du dépôt. Revers : un fichier inchangé n'apparaît pas.
- Sources : `git status --porcelain=v1 -z` et `git diff --name-only @{upstream}..HEAD` (sans amont :
  `↑` omis, une ligne « pas d'amont » en tête). Un fichier à la fois modifié et non poussé porte `●`.
- Dossiers repliables (état dans `$.state`), repliés au-delà de 20 fichiers.
- Rafraîchi après `tool.call` sur `Write`, `Edit`, `NotebookEdit`, `Bash`, `PowerShell` (`await
  next(e)` puis relecture), et au `session.start`. Hors dépôt git : panneau absent.

### Lire / Modifier
- Modifier : `plugin/mods/affichage/hooks/fichiers.ts` (créer)
- Modifier : `plugin/mods/affichage/hooks/register.tsx` (créer en T8 si absent)
- Modifier : `plugin/mods/affichage/tests/fichiers.test.ts` (créer)
- Modifier : `plugin/mods/affichage/tests/rendu.test.tsx` (créer en T8 si absent)
- Modifier : `plugin/mods/affichage/types/index.d.ts` (créer s'il n'existe pas)

### Étapes
1. Parsing pur (`fichiers.ts`) : porcelain `-z` (renommages, chemins avec espaces), non poussés →
   arbre par dossier avec icônes. Tests.
2. Panneau, rafraîchissement, `$.state` du repli ; rendu testé sur `desktop` et `mobile`.
3. `validate`, `test` ; N0 ; commit T9.

### Validation
- **N0 auto (bloque le commit)** : `node plugin/bin/n0.mjs --session P16/S5` → vert
- **Tests** : `fichiers.test.ts` (modifié, nouveau, renommé, chemin avec espace, non poussé, cumul,
  pas d'amont) ; rendu (repli au-delà de 20)
- **N1 visuel auto** : —
- **N2 humain** : en S7
- **Anti-raccourci** : parsing testé sur `--porcelain` sans `-z` alors que le code lance `-z` (ou
  l'inverse) : vert sur une sortie que le module ne reçoit jamais. Les fixtures de test reproduisent
