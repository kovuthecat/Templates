## T11 — Commande `/incidents` : les incidents de tous les projets

### Objectif
`/incidents` liste les incidents de workflow de tous les projets frères (`<parent de la racine>/*/docs/workflow/incidents/*.md`),
du plus récent au plus ancien : projet · date · titre · nature.

### Pourquoi
Rassembler sans script ni changement de projet ce que `/analyser-incidents` traite depuis Templates
(brief MVP 4) ; un incident vu dans trois projets est un défaut du workflow.

### Décision clé
- Logique d'en-tête **portée** de `plugin/bin/collecter-incidents.mjs` (lecture des champs, incident
  non conforme listé quand même, champs vides) — le mod n'a pas Node : `$.fs.list` / `$.fs.read`.
  Option `/incidents <YYYY-MM-DD>` = « depuis ». Pas de `fetch`, pas d'écriture.
- Silencieuse hors projet du workflow (pas de `.claude/workflow/manifest.json` ni de
  `plugin/.claude-plugin/plugin.json`) : la commande n'est pas enregistrée.
- Sortie `{ text }` en table markdown, 50 lignes au plus, puis « … et <n> autres ».

## Écarts au plan

- **Amendement (T10)** — la décision clé fait passer les quatre boutons par `$.prompt.submit({ text })`.
  Mesuré le 2026-10-07, sous `claude plugin test` (moteur 2.1.289) : `$.prompt.submit` **refuse** un
  texte qui commence par `/` — « submits a prompt to the model; a text beginning with / would run a
  command as the user; run one with $.command.run({ command }) (host check) ». Les boutons « Reprends »
  (`/reprendre`) et « Enchaîne l'orchestration » (`/orchestrer-plan P<n>`) passent donc par
  `$.command.run({ command, args })` ; « Go » et « Commit+push » (texte libre) restent en
  `$.prompt.submit`, soumis comme paroles de la personne (`asUser`). Les textes et préfixes du tableau
  sont inchangés ; l'objectif (relancer en un appui, la file du moteur s'appliquant) l'est aussi.
  Couvert par `plan.test.ts` (« relance ») et `rendu.test.tsx` (canal de chaque bouton).
