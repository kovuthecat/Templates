## T7 — Assembler, valider, réinstaller, contrôler le cache

### Objectif
Faire entrer les quatre modules dans le plugin de la branche, puis réinstaller le plugin
`--scope local`. À la fin, le cache doit contenir et valider les quatre modules. Toute
conversation neuve de ce projet les chargera.

### Pourquoi
Un plugin installé ne charge ses modules qu'au démarrage d'une conversation. S6 ouvrira deux
conversations neuves, et c'est là que M1 bis se mesure. Si l'installation est creuse (cache sans les
modules), S6 mesurerait du vide, comme en P12.

### Décision clé
- `plugin/hooks/hooks.json` : ajouter `"modules": ["./observateur.tsx", "./fichiers.ts",
  "./limites.ts", "./orchestration.ts"]` (chemins relatifs à `hooks.json`), sans toucher aux
  entrées existantes.
- `plugin/.claude-plugin/plugin.json` : réunir les `userConfig` de L (seuil) et d'O (`o1` à `o5`,
  actifs). **Seuil L par défaut porté à 95 % pour le passage en direct** : la vague 1 vient de
  consommer de la fenêtre de 5 h, et à 80 % le mod refuserait tous les sous-agents de S6. Le refus
  au seuil est déjà prouvé par `plugin test` en S2 (critique de plan, constat 8). Un champ `types`
  ne s'ajoute que si `validate` l'exige.
- `.gitignore` : ajouter `plans/*/*.verdict`. Les fichiers qu'O4 écrit ne sont pas commités. Non
  ignorés, ils saliraient l'arbre et bloqueraient la clôture des plans de fixture (`git status`
  propre exigé).
- Réinstallation : `claude plugin uninstall workflow@templates --scope local`, puis
  `claude plugin install workflow@templates --scope local`, puis `claude plugin list`.
  **`update` ne suffit pas** : à version égale, il ne recopie rien.

### Étapes
1. Premier geste : vérifier que `CLAUDE_CODE_PLUGIN_DIRS` est absent de `~/.claude/settings.json`
   (lecture seule). Présent → `FAIL` environnement : il fausserait M1 bis, et le retirer est un
   geste sur les réglages de l'utilisateur.
2. Copier les quatre modules et ajuster leurs imports relatifs si besoin. Les journaux restent
   distincts par mod. Trancher les écarts de format signalés au Bilan de S3, en modifiant le module
   ou en le notant pour `collecter.mjs`.
3. `hooks.json`, `plugin.json`, `.gitignore` (Décision clé).
4. `"$CLAUDE_CODE_EXECPATH" plugin validate plugin/.claude-plugin/plugin.json` → `✔`. Un module
   refusé une fois assemblé → le retirer de `"modules"`, le noter au Bilan (négatif de ce mod),
   continuer avec les autres.
5. `node tests/tester-hooks.mjs` → vert (le câblage `hooks.json` a changé).
6. Commiter (sur la branche), puis réinstaller (Décision clé) — les deux commandes à la suite,
   sans geste entre elles : l'orchestrateur en cours lit ses scripts dans ce cache.
7. Contrôler le cache `~/.claude/plugins/cache/templates/workflow/0.54.0/` :
   - `hooks/hooks.json` porte `"modules"` ;
   - les quatre modules sont présents ;
   - `"$CLAUDE_CODE_EXECPATH" plugin validate <cache>/.claude-plugin/plugin.json` → `✔` ;
   - `claude plugin list` montre `workflow@templates` actif au scope `local`.

### Validation
- **N0 auto (bloque le commit)** : `"$CLAUDE_CODE_EXECPATH" plugin validate plugin/.claude-plugin/plugin.json` → `✔`,
  `node tests/tester-hooks.mjs` → vert, `node plugin/bin/n0.mjs --session P13/S5` → PASS ; puis,
  après réinstallation, les quatre contrôles de cache de l'étape 7.
- **Tests** : — (assemblage ; chaque module a ses tests en vague 1)
- **N1 visuel auto** : —
- **N2 humain** : —
- **Anti-raccourci** : `claude plugin update` répond « déjà à jour » et tout paraît vert, mais le
  cache ne contient aucun module (P12, M1). Seul le contrôle **du cache** (étape 7) prouve
  l'installation, pas la sortie de la commande d'installation. Autre faux vert : `validate` lancé

### Si bloqué
L'installation échoue après la désinstallation : le workflow de l'utilisateur est alors sans
plugin. Réessayer une fois. Si l'échec persiste, remettre `plugin/hooks/hooks.json` et `plugin.json`
à leur état de `main` (`git restore --source=main`), réinstaller pour rendre le workflow, puis
rendre `FAIL` (nature `environnement`). Ne jamais laisser le poste sans plugin.
