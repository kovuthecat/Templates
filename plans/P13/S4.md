## T6 — Module d'orchestration, cinq hooks désactivables, et leurs tests

### Objectif
Écrire `preuves/mods/orchestration/` : un module `orchestration.ts`, cinq hooks indépendants, un
interrupteur `userConfig` par hook (`o1` à `o5`, actifs par défaut). Chaque hook est prouvé par
`plugin test` sur les cas de la décision.

### Pourquoi
Le workflow répète en prose, dans une dizaine de skills, des règles qu'un exécutant oublie : le
modèle à passer, `run_in_background`, relire `CLAUDE-BASE.md`, la collecte du verdict, la coupure de
quota. En P12, une `session-low` lancée sans `model` a tourné en Opus. Un hook rend ces règles
mécaniques. S6 dira lesquelles tiennent sur des sessions réelles.

### Décision clé
- **O1** (`agent.spawn`) : si le prompt nomme `plans/P<n>/S<k>.md`, lire la colonne Modèle (5e) de
  la ligne `S<k>` de `plans/P<n>/index.md`, et imposer ce modèle en minuscules, comme `champAgent`.
  Cela vaut quand le modèle est absent comme quand il contredit l'index. Prompt sans plan, ou index
  illisible : inchangé, **jamais un refus**.
- **O2** (`agent.spawn`, prompt réécrit) : préfixer le contenu de `CLAUDE-BASE.md` lu à la racine
  du plugin (jamais un chemin en dur), **une fois**. Un marqueur de début empêche le doublon si le
  prompt le porte déjà.
- **O3** (`tool.call` sur `Agent`, entrée réécrite) : `run_in_background` absent → ajouté à
  `false` ; `true` ou `false` explicites → inchangés.
- **O4** (`turn.complete` d'un sous-agent lancé sur `plans/P<n>/S<k>.md`) : dernière ligne
  `VERDICT:` du tour → `plans/P<n>/S<k>.verdict`. Erreur `rate_limit` sans `VERDICT:` →
  `plans/P<n>/S<k>.echec.md` avec `Nature : interruption`, `Tentatives : reprise=0 enquete=0` et
  `Agent : <agentId>`, comme l'orchestrateur le fait à la main aujourd'hui. Le `.echec.md` n'est
  jamais écrasé s'il existe. Sans `VERDICT:` ni erreur de quota, rien n'est écrit.
- **O5** (`$.ui.status`, sur `session.measure` et `turn.complete`) : plan, vague et session en
  cours. Le plan est déduit du dernier `agent.spawn` qui a nommé `plans/P<n>/` ; sans plan
  connu, la ligne n'en dit rien. Vague et session viennent de `prochaine-action.mjs P<n> --json`
  par `$.process` (accepté en P12, M4). La ligne dit aussi le % de la fenêtre de 5 h et le
  remplissage du contexte. Un rappel **unique** apparaît au franchissement de 70 % de contexte,
  le seuil d'arrêt d'`EXECUTANT.md`.
- Chaque intervention de chaque hook ajoute une ligne JSON horodatée à
  `<home>/.claude/preuves/mods/orchestration.jsonl` : hook, `agentId`, plan, session, avant/après
  (modèle, `run_in_background`, préfixe posé ou non, fichier écrit, texte d'état). C'est ce que S6
  relèvera. Aucun chemin personnel en dur.

### Lire / Modifier
- Lire : `plugin/bin/prochaine-action.mjs`
- Lire : `plugin/CLAUDE-BASE.md`
- Modifier : `preuves/mods/orchestration/` (créer) — manifeste du plugin (options userConfig o1 à o5), hooks.json qui nomme le module orchestration.ts, le module, ses tests et un index de fixture

### Étapes
1. Vérifier dans les types : retour d'`agent.spawn` (`{ model }`, `next({ ...e, model, prompt })`),
   réécriture de l'entrée d'un `tool.call`, texte final d'un sous-agent et erreur de quota sur
   `turn.complete`, `$.ui.status`, `$.process`, racine du plugin. **Un champ absent est le négatif
   de la décision pour ce hook** : l'écrire au Bilan, livrer les autres hooks.
2. Écrire le module, un hook à la fois, chacun avec ses tests :
   - O1 : modèle absent (imposé), contraire à l'index (remplacé), prompt sans plan (inchangé),
     index illisible (inchangé).
   - O2 : préfixe posé, préfixe déjà présent (pas de doublon).
   - O3 : absent (ajouté `false`), `true` (inchangé), `false` (inchangé).
   - O4 : verdict présent (`.verdict` écrit), verdict absent (rien), erreur `rate_limit` simulée
     (`.echec.md` écrit), `.echec.md` existant (pas écrasé).
   - O5 : texte rendu, rappel unique au franchissement de 70 % (pas à 71 % ensuite).
   - Interrupteur : `o3: false` → aucune réécriture (un cas suffit pour le mécanisme).
3. Gate du mod jusqu'au vert.

### Validation
- **N0 auto (bloque le commit)** : gate du mod, depuis la racine : `"$CLAUDE_CODE_EXECPATH" plugin validate preuves/mods/orchestration/.claude-plugin/plugin.json`
  → `✔`, `"$CLAUDE_CODE_EXECPATH" plugin test preuves/mods/orchestration` → verts,
  `node tests/tester-hooks.mjs` → vert ; puis `node plugin/bin/n0.mjs --session P13/S4` → PASS
  (sous verrou : l'orchestrateur committe la preuve).
- **Tests** : les dix-sept cas de l'étape 2.
- **N1 visuel auto** : — (rendu simulé seulement)
- **N2 humain** : —
- **Anti-raccourci** : un test O1 ou O3 qui vérifie la valeur **rendue par le hook** sans vérifier
  qu'elle est transmise (`next` appelé avec l'entrée réécrite, ou `{ model }` rendu). Le kit doit
  montrer l'entrée que l'outil reçoit. Autre faux vert : O4 testé avec un texte de tour qui finit
  par `VERDICT:` sur la dernière ligne seulement. Il faut aussi un cas où la ligne `VERDICT:` est
  suivie d'un retour à la ligne vide.

### Si bloqué
Un hook dont l'événement ou le champ manque → négatif de ce hook, au Bilan ; les autres se
livrent. `$CLAUDE_CODE_EXECPATH` absent → `FAIL` environnement.
