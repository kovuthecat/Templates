## T10 — Fichier de mesures

### Objectif
Écrire `docs/analyses/2026-10-05-preuves-mods-autonomes-mesures.md`. Le nom porte la date de la
décision, comme celui de P12. Il contient une section par mesure : M5, M1 bis, M2b, M3 bis, F, L,
H, O1 à O5. Chaque section donne :
- le protocole tel qu'exécuté ;
- les lignes de journal citées ;
- la commande qui reproduit ;
- le verdict contre le critère de la décision, cité mot pour mot.

Puis viennent « Réfuté », « Mods candidats », « Défauts relevés » et le **nombre de gestes humains
demandés** (cible : 0).

### Pourquoi
C'est le seul livrable de P13 qui revient sur `main`. La décision d'adopter ou non chaque mod, et
de remplacer la pastille, s'y appuiera sans relire les journaux. Un verdict non adossé à son
critère cité ne pourra pas trancher.

### Décision clé
- Ouvrir par « Ce que ça change, en clair », registre « Écrire pour qui décide »
  (`CLAUDE-BASE.md`) : quel mod tient, lequel tombe, ce que M5 dit de la pastille. Puis les
  sections techniques.
- Verdicts possibles : positif, négatif, non conclu (avec la raison : budget, quota, outil absent,
  choix manquant). Jamais « partiellement positif ».
- Un geste humain = toute carte d'approbation, tout message humain, tout clic demandé pendant P13,
  lancement de `/orchestrer-plan` excepté. Les relevés de S6 et les Bilans les donnent.

### Lire / Modifier

- Modifier : `docs/analyses/2026-10-05-preuves-mods-autonomes-mesures.md` (créer)

1. Une section par mesure, dans l'ordre de la décision. Citer le critère, puis les relevés.

3. « Défauts relevés » : ceux des Bilans de S1 à S6, et ceux de l'outillage du workflow vus en

## T11 — Mods retirés, plugin réinstallé, mesures reportées sur `main`

### Objectif
Ôter les modules du plugin de la branche et réinstaller le plugin, qui redevient celui de `main`.
Puis lancer le N0 complet, et reporter le seul fichier de mesures sur `main` **sans changer la
branche de l'arbre de travail**.

### Pourquoi
Tant que les mods restent installés, toute conversation neuve de ce dépôt les charge, et le mod F
refuserait des écritures hors preuve. La marketplace est le dossier `plugin/` de l'arbre : une
réinstallation faite sur la branche avec les mods les remettrait. Enfin, l'orchestrateur lit l'index
de la branche. Un passage de l'arbre sur `main` lui ferait voir P13 entièrement décoché, et il
relancerait la vague 1 sur `main` (critique de plan, constat 4).

### Décision clé
- Retrait sur la branche : `git restore --source=<commit du plan sur main> -- plugin/hooks/hooks.json
  plugin/.claude-plugin/plugin.json .gitignore`, puis `git rm` des quatre modules. Le commit du plan
  se retrouve par `git log --grep "plan(P13)" -1 --format=%H`. Supprimer d'abord les
  `plans/P9x/*.verdict` : sans la ligne de `.gitignore`, ils saliraient l'arbre. Leur contenu est
  déjà dans les relevés.
- Réinstallation : `claude plugin uninstall workflow@templates --scope local` puis
  `claude plugin install workflow@templates --scope local`. Contrôle **du cache** : `hooks.json`
  sans `"modules"`, aucun des quatre modules.
- Report sur `main` par un index temporaire, sans `switch` :
  ```
  git fetch origin main
  export GIT_INDEX_FILE="$(mktemp)"
  git read-tree origin/main
  git update-index --add --cacheinfo 100644,"$(git hash-object -w docs/analyses/2026-10-05-preuves-mods-autonomes-mesures.md)",docs/analyses/2026-10-05-preuves-mods-autonomes-mesures.md
  arbre="$(git write-tree)"; unset GIT_INDEX_FILE
  c="$(git commit-tree "$arbre" -p origin/main -F <fichier de message>)"
  git push origin "$c:refs/heads/main"
  ```
  Message : `docs(preuve): mesures des mods autonomes (P13)`, une ligne
  `Déroulé sur preuve/mods-2 : statuts, preuves N0 et revues y restent.`, puis la ligne
  `Co-Authored-By` d'usage. Pas de repère `Plan:` sur `main` : le repère de T11 est porté par le
  commit de la branche.
