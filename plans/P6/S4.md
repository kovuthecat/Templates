### Pourquoi

des incidents. La norme doit se lire sans payer l'histoire.

| §3 | selon la sonde A : agents `session-<effort>` **ou** effort annoncé une fois en tête d'orchestration ; l'orchestrateur est **Sonnet**, dit tel quel |

| §5b | l'état d'orchestration vient de `prochaine-action.mjs` ; retirer « l'orchestrateur tourne sur Haiku » |

### Lire / Modifier
`plugin/WORKFLOW.md`, `plugin/hooks/plafonds.json` (ajout du plafond `.echec.md` : 40 lignes — si
`lib.mjs` ne sait pas l'appliquer à un motif de chemin, l'écrire comme donnée et le signaler au bilan).

### Étapes
1. Recenser les renvois entrants : `grep -rn "WORKFLOW.md\` §" plugin/` — chaque ancre citée doit
   survivre avec le même numéro.
2. Réécrire section par section ; un paragraphe « Pourquoi / constat du … » → une ligne
   « Pourquoi : `docs/decisions/<fichier>` » (la décision existe déjà pour chacun ; sinon, le dire
   au bilan plutôt que d'en inventer une).
3. Appliquer la table ci-dessus. Chemin des scripts : `.claude/workflow/bin/` dans un projet
   vendoré, `plugin/bin/` dans le dépôt source — le dire une fois, en §5.
4. `wc -l plugin/WORKFLOW.md` < 300.

### Validation
- **N0 auto** : `node tests/tester-renvois.mjs` → OK ; `node plugin/bin/publier.mjs --dry-run` → code 0.
- **Tests** : — (prose ; les renvois sont la gate).

  formulation trahit-elle la décision ? (c'est la `validation-humaine` de la vague 4).
- **Anti-raccourci** : passer sous 300 lignes en **supprimant une règle** plutôt que son historique.
  Contrôle : chaque ligne des tables « un statut, un endroit », « nature », « ce qui arrive » de

### Si bloqué

choix non reçu : la lister au bilan, garder l'ancienne formulation, continuer.
