## T10 — `SKILL.md` : lancer, collecter, exécuter l'action rendue

### Objectif
La skill devient une boucle « appeler le script → exécuter l'action → recommencer », sous 180 lignes.

### Pourquoi
Tout ce que la skill fait suivre en prose et que le script calcule désormais est une occasion
d'erreur d'aiguillage payée en sessions Opus.

### Décision clé
- Frontmatter : retirer `model: haiku` (il ne vaut que pour le tour d'invocation — décision,
  « Vérifié ») ; écrire « Sonnet » dans le corps.
- **Sonde A confirmée** → les sessions se lancent avec `subagent_type: "session-<effort>"` (trois
  agents à créer dans `plugin/agents/`, corps = le prompt d'exécutant actuel, `effort:` en
  frontmatter, `model` passé à l'appel). **Réfutée ou non sondable** → `subagent_type: "claude"`
  inchangé, et l'action `regler-effort` du script s'annonce **une fois**, avant la première vague.
- Table « une action → un geste » : `lancer` · `verifier-premisse` · `reprendre` · `enqueter` ·
  `relire` · `pousser` · `validation-humaine` · `question` · `fini`.
- Revue : une par **vague** (C7), lancée par l'orchestrateur sur l'action `relire` — les sessions
  ne la lancent plus.
- Sous verrou : messages de commit lus dans l'`index.md` ; l'interdit « ne jamais ouvrir un
  `S<k>.md` » redevient sans exception.
- Rapport final : une ligne `subagent_tokens` par session ; une ligne par usage du canal court.
- Contrôle de version (C4) avant la première vague seulement.

### Lire / Modifier
`plugin/skills/orchestrer-plan/SKILL.md` ; selon la sonde A, créer
`plugin/agents/session-low.md`, `session-medium.md`, `session-high.md`.

### Étapes
1. Garder tels quels : « Interdits », format d'annonce de vague (Étape 3), format de question
   (Étape 6), bloc `Agent({` de session (invariants de lancement compris).
2. Remplacer Étapes 1, 2, 5 et la logique de 5c/5d par la boucle et la table des actions.
3. Étape 4 (collecte) : garder `partial` = `FAIL` et « réponse sans `VERDICT:` → vérifier les
   enfants » ; le recoupement par les commits passe au script (le dire en une ligne).
4. `pousser` : `git pull --rebase` puis `git push` ; conflit → `question`.

### Validation
- **N0 auto** : `node tests/tester-renvois.mjs` ; `node plugin/bin/publier.mjs --dry-run` (vérifie
  l'invariant de lancement dans chaque bloc `Agent({`) ; `wc -l` < 180.
- **Anti-raccourci** : une table d'actions qui ne couvre pas **toutes** les actions que le script
  sait rendre — comparer à la liste de `prochaine-action.mjs`, pas à celle de la décision.

### Si bloqué
Le script ne sait pas rendre une action dont la skill a besoin → correctif localisé s'il tient les
quatre conditions ; sinon `FAIL` prémisse, affirmation falsifiable (« `prochaine-action.mjs` ne
rend jamais X dans l'état Y »).
