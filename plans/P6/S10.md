## T23 — De l'état à l'action

### Objectif
`node plugin/bin/prochaine-action.mjs P<n> [--json]` rend **une** action parmi celles de C2.

### Pourquoi
Budget, table nature → modèle, dépendances et recoupement par les commits sont déterministes ; les
faire suivre en prose par un modèle est la première source d'erreurs d'aiguillage, payées en
sessions Opus.

### Décision clé
Les tables de `remediation.md` se reprennent **telles quelles** — ce n'est pas le moment de les
améliorer. Ordre d'évaluation : `wave.lock` présent → `question` · vague close non poussée →
`pousser` · session en échec de la vague courante → cycle de remédiation (budget d'abord) · vague
close sans revue → `relire` · `validation-humaine` · vague suivante → `lancer` · sinon `fini`.
`regler-effort` n'est rendu qu'une fois : aucun commit `Plan: P<n>/` n'existe encore.

### Lire / Modifier
`plugin/bin/prochaine-action.mjs`, `tests/tester-scripts.mjs`, `tests/fixtures/plans/`.

### Étapes
1. Moteur sur l'état de `--etat`, dans l'ordre ci-dessus.
2. Remédiation : `prémisse` sans `Mesure` → `verifier-premisse` ; avec `Mesure` (commit vérifié par
   `git cat-file -e`) → `question` ; `environnement` → `reprendre` même modèle ; `exécution` →
   un cran au-dessus, plancher Sonnet ; session Opus → `enqueter`, sauf `Blocage :` qui nomme un
   geste → `reprendre` même modèle ; `Auto : oui · option <m>` → `reprendre` avec l'option ;
   budget session (2 reprises, 1 enquête) ou plan (2 enquêtes) épuisé → `question` ;
   `reprise-manuelle` → `question`.
3. `question` porte `motif` et `options` = la **source** des options (section `## Issues` du
   rapport, ou la ligne de la table de l'Étape 6), jamais leur texte.
4. Écart `Workflow : v` index ↔ version courante : champ `avertissement`, jamais une action.
5. Sortie texte : une ligne lisible puis les champs ; `--json` : l'objet.
6. Tests, une fixture par cas : plan neuf → `regler-effort` puis `lancer` vague 1 · vague faite non
   poussée → `pousser` · close sans revue → `relire` · `validation-humaine` · `exécution` Sonnet →
   `reprendre` Opus · `prémisse` sans mesure → `verifier-premisse` · budget épuisé → `question` ·
   `Auto : oui` → `reprendre` + option · `reprise-manuelle` → `question` · `wave.lock` →
   `question` · tout coché et poussé → `fini`.

### Validation
- **N0 auto** : `node plugin/bin/n0.mjs` → tout PASS ; `node plugin/bin/prochaine-action.mjs P5` → `fini`.
- **Tests** : `tests/tester-scripts.mjs`, les onze cas.
- **Anti-raccourci** : un test qui n'asserte que le **nom** de l'action laisse passer un mauvais
  modèle de reprise — asserter aussi `modele`, `sessions` et `option`.

### Si bloqué
Deux lectures codables d'une règle de `remediation.md` → les écrire au bilan, coder la plus
prudente (celle qui rend `question`). Un défaut du parseur de S2 : correctif localisé, commit séparé.
