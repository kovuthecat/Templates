## T3 — `plugin/bin/n0.mjs`

### Objectif
Le script du contrat C1, et ses tests.

### Pourquoi
Remplace un sous-agent par une commande : même protection du contexte, zéro démarrage à froid, et
la classe d'incidents « verdict perdu à la frontière de tour » n'a plus de support.

### Référence
`plugin/agents/verificateur-n0.md` — la sortie imposée (tableau + 5 lignes d'erreur au plus) est
celle à reproduire ; la règle « jamais de commande devinée » aussi.

### Lire / Modifier
Créer `plugin/bin/n0.mjs`, `.claude/n0.json`, `tests/tester-scripts.mjs`, `tests/fixtures/n0/` (un `n0.json` vert, un
rouge dont la commande imprime une erreur au format `tsc`, un absent).

### Étapes
1. Lecture de `.claude/n0.json` ; absent ou invalide → code 2 et le message de C1, mot pour mot.
2. Exécution séquentielle, arrêt **non** anticipé (toutes les commandes tournent : le rapport est
   complet en un appel) ; délai par commande ; log complet dans `.claude/n0/dernier.log`.
3. Extraction d'erreurs : motifs `tsc` (`fichier(l,c): error`), `fichier:l:c`, lignes `FAIL`/`✗`
   de vitest/jest, ESLint ; repli = 5 dernières lignes non vides. Maximum 5 lignes rendues.
4. `--seulement <nom>` et `--cible <fichier>` (substitue `{fichier}` dans `testCible`).
5. `.claude/n0.json` **du dépôt source** : `tests/tester-hooks.mjs`, `tester-scripts.mjs`,
   `tester-renvois.mjs`, `publier.mjs --dry-run` — le dépôt source n'est pas vendoré, c'est son N0.
6. Tests : vert → code 0 et une ligne par commande ; rouge → code 1, ≤ 5 lignes, chemin du log ;
   absent → code 2 ; délai dépassé → `FAIL (délai)`.

### Validation
- **N0 auto** : `node tests/tester-scripts.mjs` → tous OK ; `node --check plugin/bin/n0.mjs`.
- **Tests** : `tests/tester-scripts.mjs`, cas ci-dessus.
- **Anti-raccourci** : un test « rouge » dont la fixture échoue pour une autre raison que l'erreur
  simulée (commande introuvable) passerait sans prouver l'extraction — asserter le **texte** extrait.

### Si bloqué
Windows vs POSIX pour lancer une commande composée : `shell: true` est le choix par défaut ; s'il
ne suffit pas, le dire — ne pas ajouter de dépendance.

### Message de commit
`feat(plugin): n0.mjs — N0 par script, sortie bornée`
`Plan: P6/S2/T3`

## T4 — `prochaine-action.mjs` : parseur d'index et état des sessions

### Objectif
La moitié « lecture » du contrat C2 : `node plugin/bin/prochaine-action.mjs P<n> --etat` rend, en
JSON, les vagues, les sessions et l'état de chacune. Le moteur d'actions est S10.

### Pourquoi
Un moteur écrit sur un parseur non éprouvé se débogue deux fois ; l'index réel a des variantes
(legacy `gate`, `Desktop`, `headless`) que seules des fixtures tirées de plans réels révèlent.

### Lire / Modifier
En plus : `plugin/skills/nouveau-plan/references/squelette-index.md` (format à parser),
`plans/P5/index.md` et `plans/P4/index.md` (index réels), `plugin/skills/reprendre-echec/SKILL.md`
(section « Gabarit » : les cinq lignes mécaniques). Créer `plugin/bin/prochaine-action.mjs`,
`tests/fixtures/plans/` ; compléter `tests/tester-scripts.mjs`.

### Étapes
1. Parseur d'index : table des sessions (tâches `T<a>-T<b>`, modèle, effort, dépendances, zone,
   statut `[ ]`/`[x]`/`[x]!`), vagues de l'ordonnancement (parallélisable, `validation-humaine`,
   `reprise-manuelle`, `pastille`, `gate` ignoré), ligne `Workflow : v` (absente = inconnue).
2. État d'une session : `faite` (statut coché, ou tous ses `T<m>` ont un commit `Plan:`),
   `echec` (`S<k>.echec.md` présent → les cinq lignes mécaniques, défauts du gabarit quand une
   ligne manque), `a-lancer`. État du dépôt : `wave.lock` présent, avance/retard sur l'amont.
3. `--etat` : sortie JSON de tout ce qui précède. Sans `--etat` : « moteur non implémenté (S10) », code 2.
4. Tests : fixture copiée de `plans/P5/index.md` → 9 sessions, 6 vagues, toutes `faite` ; fixture
   du squelette ; `.echec.md` complet, puis sans `Tentatives :` ni `Blocage :`.

### Validation
- **N0 auto** : `node tests/tester-scripts.mjs` ; `node plugin/bin/prochaine-action.mjs P5 --etat`
  → JSON valide, 9 sessions `faite`.
- **Anti-raccourci** : des fixtures écrites d'après le parseur valident le parseur contre lui-même —
  au moins une fixture est une **copie** d'un index réel.

### Si bloqué
Un index réel que le parseur ne peut pas lire sans deviner → le lister au bilan ; le parseur rend
une erreur nommée (`index illisible : <ligne>`), jamais un état supposé.

### Message de commit
`feat(plugin): prochaine-action.mjs — parseur d'index et état des sessions`
`Plan: P6/S2/T4`
