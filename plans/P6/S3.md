## T5 — `stop-contexte.mjs` : gate de push, revue commitée

### Objectif
Le hook refuse de rendre la main sur des commits non poussés ou des fichiers suivis modifiés (C3),
et ne cherche plus le repère `Revues:`.

### Pourquoi
C'est la seule application mécanique de « tout travail rendu est reprenable d'un autre poste » ;
une règle seulement écrite a déjà laissé un clone deux semaines en retard (2026-09-09).

### Lire / Modifier
`plugin/hooks/stop-contexte.mjs`, `plugin/hooks/lib.mjs`, `tests/tester-hooks.mjs`, `.claude/settings.json`.
`pretooluse-git.mjs` ne change pas : sous `wave.lock` la règle de push est **suspendue** (C3).

### Étapes
1. Nouveau manquement « non poussé » : `etatAmont().avance > 0`, ou `git status --porcelain` avec
   des fichiers **suivis** modifiés. Exemptions de C3 ; hors ligne = un `git push --dry-run` qui
   échoue sur le réseau → signaler, ne pas bloquer.
2. Branche sans amont (`wip/…`, branche de preuve, branche cloud) : le manquement devient
   « branche non poussée » (`git ls-remote --heads origin <branche>` vide).
3. Revue : `revuesManquantes` (`lib.mjs`) lit **git**, plus le disque — une revue existe si
   `git log --diff-filter=A -- plans/P<n>/S<k>.revue.md` rend un commit ; le tri de clôture la
   supprime ensuite sans recréer le faux positif que le repère `Revues:` évitait (commentaire de
   `lib.mjs` au-dessus de la fonction). Retirer alors la lecture de `Revues:`. Garder « bloque une
   fois, ne rappelle que si la liste change ».
4. Tests : avance 1 → bloque ; à jour → muet ; sans remote → muet ; `wave.lock` → muet sur ce
   point ; `.revue.md` commité → contrôle de revue satisfait.
5. `.claude/settings.json` **du dépôt source** : ajouter à `permissions.allow` `git push`,
   `git pull --rebase`, `node tests/*`, `node plugin/bin/n0.mjs`, `node plugin/bin/prochaine-action.mjs`
   — sans elles, les sessions orchestrées des vagues suivantes restent bloquées sur une invite.
   (Élargissement approuvé par l'utilisateur avec ce plan ; rien d'autre ne s'y ajoute.)

### Validation
- **N0 auto** : `node tests/tester-hooks.mjs` → tous OK ; `node --check` sur les deux hooks.
- **Anti-raccourci** : tester « à jour » sur un dépôt **avec** remote (un `git init --bare` local) —
  sans remote, le cas passe par l'exemption et ne prouve rien.

### Message de commit
`feat(hooks): Stop refuse un travail non poussé ; revue commitée`
`Plan: P6/S3/T5`

## T6 — `sessionstart-contexte.mjs` : version du workflow vendoré

### Objectif
Une ligne au démarrage quand `.claude/workflow/manifest.json` est en retard sur le dernier tag
publié (C4) ; rien sinon.

### Étapes
1. `lib.mjs` : `derniereVersionPubliee(cwd)` — cache `.git/workflow-version.json`
   (`{ version, lu }`), TTL 24 h ; sinon `git ls-remote --tags --sort=-v:refname <source>` (`manifest.json`, champ `source` —
   c'est un slug `proprietaire/depot` : l'URL est `https://github.com/<slug>`), délai 3 s, échec → `null` sans écrire le cache.
2. Hook : manifeste présent **et** version publiée > version vendorée → ligne « Workflow vendoré
   v… , source v… — `/maj-workflow` à la prochaine frontière de plan » ; si
   `correctifCritiqueDepuis` s'applique : « …**avant la prochaine vague** ». Dépôt non vendoré
   (pas de manifeste) → muet.
3. Comparaison de versions numérique (`0.9.0 < 0.38.1`), pas lexicale.
4. Tests : cache frais lu sans réseau ; retard → ligne ; à jour → muet ; pas de manifeste → muet.

### Validation
- **N0 auto** : `node tests/tester-hooks.mjs`.
- **Anti-raccourci** : un test qui laisse le hook joindre le vrai dépôt public est lent et
  non reproductible — injecter la source par une variable d'environnement de test ou le cache.

### Message de commit
`feat(hooks): SessionStart signale un workflow vendoré en retard (cache 24 h)`
`Plan: P6/S3/T6`

## T7 — `publier.mjs` : tag `v<version>`

### Objectif
Chaque publication pose et pousse le tag de sa version sur le dépôt public.

### Pourquoi
Sans tag, T6 n'a rien à lire : `git ls-remote` ne voit pas le contenu de `plugin.json`.

### Étapes
1. Après le push `HEAD:main` : `git tag v<version>` dans le dépôt temporaire, `git push --force
   <dépôt> v<version>` (le dépôt temporaire est neuf à chaque fois : le tag pointe le commit publié).
2. Vérification post-push existante : ajouter `ls-remote --tags` contient `v<version>`.
3. `--dry-run` : annoncer le tag, ne rien pousser.

### Validation
- **N0 auto** : `node plugin/bin/publier.mjs --dry-run` → annonce `tag v0.38.1`, code 0.
- **Anti-raccourci** : ne **pas** publier pour tester — la publication réelle est S9.

### Si bloqué
—

### Message de commit
`feat(publier): tag v<version> à chaque publication`
`Plan: P6/S3/T7`
