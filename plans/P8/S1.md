## T1 — Appel d'agent prêt à recopier (D2)

### Objectif
Chaque session de `lancer`, et l'action `reprendre` / `enqueter`, porte un champ
`agent: { subagent_type: "session-<effort>", model: "<sonnet|opus|haiku>" }`.

### Pourquoi
L'orchestrateur recopie aujourd'hui `model: "Sonnet"` depuis l'index : l'outil `Agent` le refuse
(`InputValidationError`, enum en minuscules — sondé le 2026-09-22), donc chaque lancement échoue au
premier essai. Et pour une reprise, il compose `session-<effort>` via une table modèle → effort
qu'il applique à la main. Le script connaît déjà les deux valeurs : il les rend, l'orchestrateur ne
transforme plus rien (C2).

### Décision clé
`docs/decisions/2026-09-22-flous-du-workflow.md`, D2. Champ **ajouté** : `modele` et `effort`
restent tels quels (affichage, bandeau de vague, tests existants).

### Lire / Modifier
Modifier : `plugin/bin/prochaine-action.mjs`, `tests/tester-scripts.mjs`. Ceinture : les cas
existants qui comparent la sortie de `lancer` / `reprendre` champ à champ — s'ils cassent parce
qu'un champ est ajouté, adapter la comparaison, jamais retirer le champ.

### Étapes
1. Une fonction `appelAgent(modele, effort)` → `{ subagent_type: \`session-${effort}\`, model: modele.toLowerCase() }`.
   Modèle hors `Sonnet|Opus|Haiku` → ne pas inventer : pas de champ `agent` et un champ
   `avertissement` nommant la valeur (le cas `effort` invalide rend déjà `question`, ne pas le toucher).
2. `lancer` : chaque élément de `sessions` reçoit `agent: appelAgent(s.modele, s.effort)`.
3. `reprendre` et `enqueter` : `agent: appelAgent(modele, EFFORT_DU_MODELE[modele])` avec la table
   Opus → `high`, Sonnet → `medium`, Haiku → `low` (celle de `references/remediation.md` l. 11-15 —
   c'est désormais le script qui la porte).
4. `formaterTexte()` : pour ces actions, une ligne par appel, lisible
   (`S1 → subagent_type: session-low · model: sonnet`), pour la sortie sans `--json`.
5. En-tête de contrat du script : documenter le champ `agent`.

### Validation
- **N0 auto (bloque le commit)** : `node plugin/bin/n0.mjs` → quatre commandes `PASS` — **jamais un sous-agent** (C1).
- **Tests** : dans `tests/tester-scripts.mjs`, trois cas : `lancer` à efforts mêlés
  (`moteur-efforts-melanges`) → S1 `{session-low, haiku}`, S2 `{session-medium, sonnet}` ;
  `reprendre` échec exécution Sonnet → `{session-high, opus}` ; `enqueter` → modèle et effort cohérents.
- **N1 visuel auto** : —
- **N2 humain** : —
- **Anti-raccourci** : un test qui vérifie `agent.model === 'sonnet'` sur une fixture où l'index écrit
  déjà `sonnet` en minuscules prouve rien — la fixture doit écrire `Sonnet`/`Haiku` capitalisés.

## T2 — Arrêt sur arbre sale dans la zone de la vague (D1)

### Objectif
Avant de rendre `lancer`, croiser les changements non commités avec les zones des sessions à
lancer ; au moindre recoupement, rendre `question` source `arbre-sale` au lieu de `lancer`.

### Pourquoi
Le texte d'`orchestrer-plan` délègue ce contrôle à `resumeur-git` ; mesuré, la moitié des
orchestrateurs lancent `git status` eux-mêmes, sans lien avec l'effort. Un contrôle trivial et
mécanique appartient au script (C2) : il devient identique à chaque fois.

### Décision clé
`docs/decisions/2026-09-22-flous-du-workflow.md`, D1. Règles fixées par la critique du plan :
- **Chemins d'une zone = seuls les segments entre backticks** de la cellule « Zone modifiée » ; le
  texte hors backticks est ignoré (`(§9a, §9c)`, `(4 fichiers créés)`, `(nouveau)`, `§5`).
- Accolades développées avant comparaison : `` `plugin/skills/{a,b}/SKILL.md` `` → deux chemins.
- Comparaison : segment terminé par `/` = dossier → préfixe ; sinon égalité de chemin.
- Segment contenant `*` ou `**`, ou accolades non appariées → zone illisible → `question`
  `arbre-sale`, motif « zone illisible : <segment> ».
- `git status --porcelain -z --untracked-files=all` : chemins bruts (pas de guillemets, pas de
  repli `?? dossier/`) ; pour un renommage, les deux chemins comptent.
- `git status` en échec (exception ou délai de `git()`) → `question` `arbre-sale`, motif « arbre
  invérifiable » — jamais un `lancer` sur un état non vérifié (C2 : jamais un état deviné).
- Fichiers du plan en cours (`plans/P<n>/`) : ignorés, sauf s'ils sont nommés par une zone.
- Session à zone `aucune` : aucun contrôle pour elle.

### Lire / Modifier
Modifier : `plugin/bin/prochaine-action.mjs`, `tests/tester-scripts.mjs`, `tests/fixtures/plans/`
(nouvelles fixtures seulement).

### Étapes
1. `cheminsDeZone(cellule)` → `{ chemins: [...], illisible: <segment|null> }` selon les règles.
2. `fichiersSales()` → liste depuis `git status --porcelain -z --untracked-files=all`, ou `null` si git échoue.
3. Dans `prochaineAction()`, juste avant le `return { action: 'lancer', … }` : pour les sessions de
   `aLancer`, calculer l'intersection. Non vide, zone illisible ou `null` → `question`,
   `options: { source: 'arbre-sale', session, fichiers | segment }`, motif lisible.
4. `formaterTexte()` : la question liste les fichiers en cause.
5. En-tête de contrat : la source `arbre-sale` et ses trois motifs.

### Validation
- **N0 auto (bloque le commit)** : `node plugin/bin/n0.mjs` → quatre commandes `PASS`.
- **Tests** : cas dans `tests/tester-scripts.mjs`, dépôt git jetable (`initDepot`) :
  arbre propre → `lancer` ; fichier modifié dans la zone → `question` `arbre-sale` le nommant ;
  fichier modifié hors zone → `lancer` ; **dossier entier non suivi** contenant un fichier d'une zone
  → `question` ; **chemin accentué** dans la zone → `question` ; cellule recopiée de
  `plans/P4/index.md:25` (accolades) avec un fichier sale d'une des branches → `question` ; cellules
  recopiées de `plans/P4/index.md:23` et `plans/P7/index.md:31` (texte hors backticks), arbre propre
  → `lancer` (**pas** de question) ; zone `` `src/**` `` → `question` motif « zone illisible ».
- **N1 visuel auto** : —
- **N2 humain** : —
- **Anti-raccourci** : des fixtures où le fichier sale est écrit à la main dans la sortie simulée de
  git ne testent pas le parsing de `-z` — les cas passent par un vrai dépôt git jetable et de vrais
  fichiers.
