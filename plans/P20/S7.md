## T11 — `prochaine-action.mjs --appliquer`

### Objectif
Avec `--appliquer`, le moteur exécute lui-même les actions **mécaniques** et enchaîne jusqu'à une
action qui demande un agent ou un humain (`lancer`, `reprendre`, `enqueter`, `relire`,
`verifier-premisse`, `transmettre`, `question`, `validation-humaine`, `fini`), qu'il rend avec son
texte (S5). Mécanique = :
- cocher `[x]` une session dont toutes les tâches sont commitées et la preuve N0 valide ;
- `[x]` → `[x]!` quand une `.revue.md` porte `Bloquant : n > 0` ;
- committer une `.revue.md` déposée (message `revue(P<n>): S<k> relue, <n> bloquant(s)`, repère
  `Plan: P<n>/S<k>`) ;
- `valider-n0` : lancer N0 `--session`, committer la preuve si vert (sinon rendre l'action, jamais
  fabriquer une preuve) ;
- `pousser` (`pull --rebase` puis `push` ; conflit → `rebase --abort` puis `question rebase`) ;
- incrémenter ou créer `Remédiation Opus :` quand il rend une passe Opus ;
- écrire la ligne `Premisse :` rendue par l'orchestrateur (option `--premisse <verdict> <preuve>`) ;
- `.echec.md` d'interruption (option `--interruption S<k> --agent <id>` passée par l'orchestrateur
  quand le retour correspond au motif de quota) ;
- `· validée` sur la ligne de vague (option `--valider-vague <w>` après ton « oui ») ;
- clôture, points 1-3 et 5 de `fin-de-plan.md` (`git status`, revues commitées, `Clos : <date>`) —
  points 4 et 6 rendus comme action `cloturer` avec ce qu'il reste à faire.
Après la dernière écriture d'un appel, le moteur **se rappelle lui-même** : un plan qui finit rend
`fini` dans le même appel (constat C).

### Pourquoi
Ces gestes sont tous mécaniques (le moteur a déjà décidé), mais Haiku les fait à la main, en oublie
(S2, S4, S5 de P19 non cochées ; rappel final omis dans trois passages sur cinq) et les paie en
lignes de skill. Les faire dans le moteur les rend testables et réduit l'orchestrateur à deux gestes :
lancer des agents, te transmettre des questions.

### Décision clé
- **D'abord committer ses propres écritures en attente** (critique du plan, constat 7) : au début de
  chaque appel `--appliquer`, si `index.md`, `.revue.md`, `.echec.md`, `.question.md` ou `*.n0.json`
  du plan sont modifiés et non commités, le moteur les committe (message `chore(P<n>): écritures du
  moteur reprises après interruption`) avant de décider. Un arrêt entre écriture et commit ne laisse
  donc jamais un arbre sale à une question humaine.
- Sans `--appliquer`, comportement actuel inchangé (lecture seule) : les mods et `noter.mjs` lisent
  le moteur sans rien écrire.
- Les commits du moteur portent l'attribution standard du dépôt (dernière ligne `Plan:`), jamais
  `--no-verify` : les hooks git s'appliquent à lui aussi.
- `noter.mjs` (constat 6) : avec `--appliquer`, un appel au moteur peut enchaîner plusieurs actions ;
  le critère « dernier appel rend `fini` » lit la **première ligne de la dernière action** de la sortie.

### Étapes
1. Cas sur dépôt jetable, un par geste : l'état avant, l'appel `--appliquer`, l'état après (fichier,
   ligne, commit et son message) ; écrire chaque cas avant le code et le voir échouer.
2. Enchaînement : une boucle bornée (au plus N tours, N = nombre de sessions × 4) qui s'arrête sur la
   première action non mécanique ; au-delà, `question` (jamais une boucle infinie).
3. Reprise d'écritures en attente ; cas d'interruption : écrire `[x]` sans committer, rappeler →
   arbre propre et commit de reprise.
4. Clôture : points mécaniques, puis `cloturer` avec le reste ; un plan dont la clôture est faite
   rend `fini` dans le même appel.
5. `noter.mjs` : dernière action d'une sortie enchaînée, testée sur un flux fabriqué à partir de
   `flux-nominal.jsonl` (S5) où le dernier appel porte une sortie enchaînée. Pas de passage réel ici :
   la skill d'orchestration ne passe à `--appliquer` qu'en S12 ; S13 le mesure.

### Validation
- **N0 auto (bloque le commit)** : `node plugin/bin/n0.mjs --session P20/S7` → vert
- **Tests** : un cas par geste mécanique ; enchaînement borné ; reprise après interruption ;
  clôture → `fini` dans le même appel ; sans `--appliquer`, aucune écriture (arbre identique).
- **N1 visuel auto** : —
- **N2 humain** : —
- **Anti-raccourci** : un test qui vérifie la ligne cochée sans vérifier le **commit** (message et
  repère) laisse passer une écriture non committée — c'est l'état qui transformait une interruption
  en question humaine.

### Si bloqué
Contrat : la sortie du moteur peut enchaîner plusieurs actions sous `--appliquer`. Les lecteurs
(mods, `noter.mjs`) lisent sans `--appliquer` ou la dernière action : pas d'arrêt.
