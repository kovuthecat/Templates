## T12 — Les chemins sensibles sont toujours relus ; `n0.json` hors zone bloque

### Objectif
1. Une liste de **chemins sensibles** décide de la relecture, en plus de l'effort : une session `low`
   ou un diff de pur Markdown qui touche un chemin sensible est relu (moteur : action `relire` ;
   relecteur : pas de saut).
2. Une modification de `.claude/n0.json` par une session dont la **zone** ne le contient pas est un
   **bloquant**, posé par le moteur (pas par le relecteur) : la session passe `[x]!` avec le motif.

### Pourquoi
La revue a montré deux angles morts : une session `low` ou un diff Markdown n'est jamais relu, alors
que les règles du workflow sont du Markdown ; et la preuve N0 ne compare `n0.json` qu'à lui-même, donc
une session peut affaiblir la gate qui la juge sans que rien ne le signale.

### Décision clé
- Chemins sensibles, une liste **dans le code du moteur** (une constante, testée), pas dans un texte :
  `CLAUDE.md`, `.claude/` (tout, dont `n0.json`, `settings*.json`, `workflow/`), les manifestes et
  lockfiles de dépendances (`package.json`, `package-lock.json`, `pnpm-lock.yaml`, `requirements*.txt`,
  `pyproject.toml`, `Cargo.toml`, `go.mod`), `.github/workflows/` ; et, dans le dépôt source,
  `plugin/bin/`, `plugin/hooks/`, `plugin/agents/`, `plugin/skills/`, `plugin/*.md`,
  `plugin/templates/`. L'exécutant peut compléter la liste par ce que le point 8 de la revue nomme
  en plus, en le citant.
- Le relecteur reçoit, dans son prompt (rendu par le moteur depuis S5), la liste des fichiers
  sensibles touchés par la session, et ne saute pas leur diff.
- `n0.json` hors zone : contrôle **mécanique** du moteur au moment de `relire` (diff des commits
  `Plan: P<n>/S<k>/` sur `.claude/n0.json`, comparé à la colonne « Zone modifiée » via le lecteur
  d'index). Bloquant → la `.revue.md` reçoit une ligne `Bloquant moteur : n0.json modifié hors zone`
  et le compte de bloquants l'inclut ; la suite (`[x]!`, `dependance-revue`) est celle d'un bloquant
  de relecture.

### Étapes
1. Constante des chemins sensibles et fonction `toucheSensible(fichiers)` ; cas : `.claude/n0.json`,
   `plugin/skills/x/SKILL.md`, `README.md` (non sensible).
2. `relire` : une session `low` qui touche un chemin sensible est relue ; une `low` qui n'en touche
   pas ne l'est pas (comportement actuel).
3. Relecteur : la liste des sensibles touchés arrive par le prompt ; il ne saute pas leur diff, même
   Markdown.
4. `n0.json` hors zone → bloquant moteur ; dans la zone → rien.
