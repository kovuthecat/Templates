## T9 — Créer le template `DESIGN_SPEC.md`

### Objectif
Un fichier copié dans chaque projet à UI : brief envoyé tel quel à Claude Design + état de la
maquette + état du kit Design Sync. Il remplace la double casquette d'ARCHITECTURE.md.

### Décision clé
D-P2-7. Faits vérifiés à respecter : Design Sync pousse un **kit de composants** vers un projet
« design system » claude.ai — un fichier **HTML autonome par composant**, 1ʳᵉ ligne
`<!-- @dsCard group="…" -->`, sync incrémentale. L'unité est le composant, pas la page : pour
reproduire une page existante, ses composants doivent être dans le kit. Le repo reste la source
de vérité du code ; les exports de maquettes restent dans `design/maquettes/` (HTML).

### Lire / Modifier
Créer : `DESIGN_SPEC.md`.

### Étapes
1. En-tête : rempli après PROJECT_BRIEF, avant la maquette ; **auto-suffisant** (Claude Design ne
   voit QUE ce fichier — recopier le strict nécessaire du brief, ne renvoyer vers rien) ; projet
   sans UI → ne pas copier ce fichier.
2. Sections brief (reprises de l'actuel ARCHITECTURE.md, mêmes intitulés) : Rappel produit ·
   Écrans & vues (un bloc par écran : rôle, contenu, actions) · Navigation & parcours ·
   Données affichées · Contraintes UI.
3. Section « Design system — sync » (projets existants, optionnelle au départ) : id du projet
   design-system claude.ai · date de dernière sync · composants couverts (nom + groupe `@dsCard`) ·
   rappel : composant absent du kit = Claude Design improvisera, synchroniser AVANT de dessiner
   un écran qui le réutilise.
4. Section « Maquette — retour » (reprise de l'actuel §Maquette UI) : statut (à dessiner /
   dessinée / câblée) · exports `design/maquettes/` · écarts maquette ↔ spec, à répercuter dans
   les sections du haut si structurants.
5. Longueur cible du template : ≤ 70 lignes.

### Validation

  seules les mentions `design/maquettes/` et la section sync y échappent).
