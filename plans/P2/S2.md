## T5 — Agent `explorateur`

### Objectif
Localiser fichiers/symboles/conventions sans polluer le contexte parent.

### Décision clé
`description` (en anglais, c'est elle qui déclenche la délégation) : « Proactively locates files,
symbols and conventions in the repository. Use whenever finding something would require scanning
more than one file. Returns only paths + roles, never file dumps. »
`tools: Read, Grep, Glob` · `maxTurns: 15`.

### Lire / Modifier
Créer : `agents/explorateur.md`.

### Étapes
1. Frontmatter selon la doc. 2. Prompt : sortie = liste `chemin — rôle (1 ligne)` + réponse à la
question posée, ≤ 20 lignes au total.

### Validation
- **N0 auto** : frontmatter YAML parse (lecture visuelle + `node --check` non applicable — vérifier
  la syntaxe contre l'exemple de la doc) ; nom en kebab-case ; description < 4 lignes.
- **N1** : — · **N2** : —

### Si bloqué
Champ frontmatter refusé par la doc → STOP, consigner.

### Message de commit (appliqué en fin de plan)
`feat(agents): explorateur (haiku, lecture seule)`

## T6 — Agent `verificateur-n0`

### Objectif
Lancer build/typecheck/tests et ne remonter QUE le verdict + les erreurs pertinentes — la sortie
de build est le plus gros pollueur de contexte du workflow.

### Décision clé
`description` : « Proactively runs build, typecheck and test commands. Use immediately after any
code change instead of running these commands in the main conversation. Returns PASS/FAIL per
command plus only the relevant error lines (file:line + message), never raw output. »
`tools: Bash, PowerShell, Read, Grep` · `maxTurns: 12`. Le prompt précise : lire les commandes
dans le CLAUDE.md du projet (§Commandes), jamais les deviner ; FAIL sans cause claire → citer les
5 lignes d'erreur les plus significatives, pas le log entier.

### Lire / Modifier
Créer : `agents/verificateur-n0.md`.

### Étapes
1. Frontmatter. 2. Prompt : format de sortie = tableau `commande → PASS/FAIL` + bloc erreurs
(fichier:ligne — message, 1 ligne chacune).

### Validation / Si bloqué / Commit
Identiques à T5. Commit : `feat(agents): verificateur-n0 (haiku, N0 délégué)`

## T7 — Agent `resumeur-git`

### Objectif
Résumer diff/historique/état git pour le cadrage sans coller de diff brut dans le contexte Opus.

### Décision clé
`description` : « Summarizes git state, diffs and history. Use when a plan or review needs to know
what changed without reading raw diffs. Read-only: never stages, commits or pushes. »
`tools: Bash, PowerShell, Read` · `maxTurns: 10`. Prompt : commandes git en lecture seule
uniquement ; sortie = par fichier : nature du changement en 1 ligne + signaux notables (TODO,

### Lire / Modifier

## T8 — Agent `lecteur-doc`

### Objectif
Aller lire une doc externe et rendre la réponse, pas la page.

### Décision clé
`description` : « Fetches and reads external documentation pages. Use whenever an answer requires
reading a web page or online docs. Returns the answer with source URLs, never the page content. »
`tools: WebFetch, WebSearch, Read` · `maxTurns: 10`. Prompt : répondre à LA question posée,
citer les URL consultées, ≤ 25 lignes ; info introuvable → le dire, pas de connaissance de mémoire
pour les produits qui évoluent vite.

### Lire / Modifier
Créer : `agents/lecteur-doc.md`.

### Validation / Si bloqué / Commit
