## T1 — Contrat « sans commande » dans `n0.mjs` et `verifier-plan.mjs`

### Objectif
`.claude/n0.json` peut déclarer `{ "commandes": [], "sansCommande": "<motif>" }`. `verifier-plan`
accepte alors `Preuve N0 : non requise` pour un nouveau plan, et le refuse dans tout autre cas.
`n0.mjs` ne rend jamais de vert sur une liste vide.

### Pourquoi
Sur trames-consultation, un projet documentaire a reçu `Preuve N0 : requise` sur cinq plans, avec
une dérogation à chaque fois (J14). Le motif obligatoire empêche un projet de code de s'exempter de
N0 en une ligne, ce qui donnerait un vert vide permanent.

### Décision clé
- « Projet sans commande » = `n0.json` **présent**, `commandes: []`, `sansCommande` chaîne non vide.
  `n0.json` absent reste une erreur. `commandes` non vide **et** `sansCommande` → incohérent, erreur.
- `n0.mjs` avec `commandes: []` : **toujours sortie 2** (jamais 0). Deux messages distincts :
  - avec `sansCommande` : « projet déclaré sans commande (<motif>) : pas de N0, les plans portent
    `Preuve N0 : non requise` » ;
  - sans `sansCommande` : « aucune commande : les reporter depuis `CLAUDE.md` § Commandes ; un
    projet sans build ni test l'écrit `"sansCommande": "<motif>"` ». Ce message ne propose
    `non requise` qu'au second cas, jamais en premier.
- `verifier-plan.mjs`, **nouveau plan seulement** (`--extension` inchangé), lit
  `<racine>/.claude/n0.json` (racine = `process.cwd()`, comme aujourd'hui) :

  | Index | `n0.json` | Résultat (contrôle 7) |
  | --- | --- | --- |
  | `requise` | commandes non vides | OK (inchangé) |
  | `requise` | `sansCommande` | écart « projet sans commande (<motif>) : écrire `Preuve N0 : non requise` » |
  | `non requise` | `sansCommande` | OK ; une tâche peut alors porter `N0 auto : — (<motif>)` |
  | `non requise` | autre | écart « `non requise` exige `.claude/n0.json` avec `sansCommande` » |
  | l'une ou l'autre | absent ou illisible | écart « créer `.claude/n0.json` (commandes de `CLAUDE.md` § Commandes, ou `sansCommande`) » |
  | aucune ligne | — | écart actuel, message élargi aux deux valeurs |

  Le contrôle 3 (l.61, commande `N0 auto` entre backticks) n'est relâché que dans la ligne OK
  `non requise`. Dans ce cas, `N0 auto : —` suivi d'un motif est accepté.

- Modifier : `plugin/bin/verifier-plan.mjs`
- Modifier : `tests/tester-preuves.mjs`
- Modifier : `tests/tester-scripts.mjs`

### Étapes
1. `n0.mjs` : accepter `sansCommande`, et produire les deux messages ci-dessus, en sortie 2. Mettre

2. `verifier-plan.mjs` : la table ci-dessus. Le message d'écart cite le motif de `sansCommande`, pour

3. `tests/tester-preuves.mjs` (cas `verifier-plan`, à côté de `:74`) : un cas par ligne de la table,
   plus « `non requise` + tâche `N0 auto : — (motif)` → RAS ». Le dépôt fixture de `depot()` écrit

4. `tests/tester-scripts.mjs` (bloc `n0.mjs`, `:101-140`) : liste vide sans `sansCommande` → 2 et
   message « CLAUDE.md § Commandes » ; avec `sansCommande` → 2 et message « non requise » ;

## T2 — Les textes qui lancent N0 connaissent `non requise`

### Objectif
Le cadreur sait quand écrire `non requise`. L'exécutant ne lance plus N0 sur un plan `non requise`
et le consigne au bilan.

### Pourquoi
Sans T2, `verifier-plan` accepte le plan, puis `/fin-de-tache` (« sinon la tâche n'est pas finie »)
fait lancer `n0.mjs` à chaque tâche. La sortie 2 passe pour une erreur de configuration, et J14 se
reproduit une étape plus loin (critique du plan, constat 2).

### Décision clé
- Une seule formule, partout : « index `Preuve N0 : non requise` → N0 sauté ; bilan
  `N0 : — (non requise : <motif de sansCommande>)` ». Dans `CLAUDE-BASE.md`, chargé à chaque
  session, **une clause courte au plus**, qui renvoie à `EXECUTANT.md`.
- `/nouveau-plan` Étape 3 : écrire `non requise` **seulement si** `.claude/n0.json` porte
  `sansCommande` ; sinon `requise`. `verifier-plan` le contrôle (T1), le texte le dit.
