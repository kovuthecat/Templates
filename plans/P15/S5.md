## T7 — Module témoin, projet de fixture, mesure K

### Objectif
Écrire un module minimal qui note `session.start`, le valider, le déclarer dans le `.claude/settings.json`
d'un projet vendoré sans plugin, ouvrir une session neuve, et voir s'il a écrit sa ligne ; sinon,
installer le même module en plugin dans ce projet pour vérifier que l'instrument voit les mods.

### Pourquoi
Si un projet peut câbler un mod comme il câble déjà ses hooks, les mods adoptés (O1, O3, O5) se
distribuent sans aucune installation, et le plan du chantier des mods prend cette voie ; sinon, il
prend celle du mini-plugin installé par `/maj-workflow`. C'est la seule mesure dont ce plan dépend.

### Décision clé
- Seule voie documentée : la clé `"modules"` du `hooks/hooks.json` d'un plugin installé
  (`"modules": ["./x.ts"]`). K éprouve une voie **non documentée** : une clé `"modules"` au niveau
  racine du `.claude/settings.json` d'un projet.
- Module : charger la skill `plugin-authoring` pour son API, puis écrire le plus petit module qui, au
  démarrage d'une session, ajoute une ligne JSON `{"evt":"session.start","cwd":…,"iso":…}` à
  `~/.claude/preuves/p15-k.jsonl`. Il vit dans un mini-plugin du dépôt :
  `preuves/session-neuve/k/.claude-plugin/plugin.json` (nom **`p15-k-temoin`**),
  `preuves/session-neuve/k/.claude-plugin/marketplace.json` (nom **`p15k`**, un plugin, `source: "./"`,
  forme de `plugin/.claude-plugin/marketplace.json`), `preuves/session-neuve/k/hooks/hooks.json`
  (`{ "modules": ["./journal.ts"] }`), `preuves/session-neuve/k/hooks/journal.ts`. Noms distincts de
  `templates` et `workflow`.
- **Validation préalable obligatoire** (piège P12, `docs/analyses/2026-10-05-preuve-mods-mesures.md`,
  « Défauts relevés » 1) : valider le **`plugin.json`**, pas le dossier — `claude plugin validate
  preuves/session-neuve/k` ne valide que le manifeste de marketplace et laisse passer un module
  refusé. Commande : `claude plugin validate preuves/session-neuve/k/.claude-plugin/plugin.json`
  (même moteur que celui qui chargera le module) → ✔ sur le module, sortie citée. Sans ✔, K ne se
  joue pas : « non conclu : module invalide ».
- Projet de fixture : `~/preuves-p15/k` (hors de tout dépôt) — `git init`, vendoring par
  `node plugin/bin/sync-workflow.mjs --source plugin --projet ~/preuves-p15/k`, puis
  `.claude/settings.json` = `plugin/templates/project-settings.json` (hooks classiques), plus
  `journal.ts` copié en `~/preuves-p15/k/.claude/mods/journal.ts`.
- `claude` : en PowerShell (`claude …`) ou `~/.local/bin/claude.exe` en Git Bash (le `claude` de Git
  Bash est un wrapper cassé). Session neuve = `claude -p "Réponds OK."` lancé avec ce projet comme
  dossier courant, délai 120 s.
- Une ligne compte si elle est postérieure au T0 de son essai et porte le `cwd` de la fixture.
- Critère, cité mot pour mot : **K** — Positif : « dans un projet de fixture vendoré sans plugin
  installé, un module déclaré dans `.claude/settings.json` écrit sa ligne `session.start` dans une
  session neuve ; module validé au préalable par `plugin validate` (piège P12) » ; Négatif : « ligne
  absente avec un module valide ».
- Lecture du témoin positif (essai 3) : ligne présente → l'instrument voit les mods, l'absence aux
  essais 1 et 2 est un vrai **négatif** ; ligne absente → « non conclu : instrument (`claude -p` ne
  charge pas ce mod) », jamais négatif.

### Lire / Modifier

- Modifier : `preuves/session-neuve/k/.claude-plugin/marketplace.json` (créer)

### Étapes

7. Relevés, section `## K` : module (chemin, sortie de `plugin validate`), fixture, chaque essai
