## T9 — Rendu, puis report sur `main`

### Objectif
Écrire `docs/analyses/2026-10-06-session-neuve-mesures.md` d'après les relevés, puis le reporter seul
sur `origin/main` — étape nommée, exécutée par cette session, autorisée par la règle `P15 —` du
report (leçon 3).

### Pourquoi
C'est le seul livrable de la preuve : la décision d'intégration (`/orchestrer-plan`, `WORKFLOW.md`
§5b) et le plan du chantier des mods (au vu de K) se prendront sur `main`, à partir de ce fichier. En
P14, le report a été refusé et fait sur ordre direct ; ici, son exécution est elle-même une mesure.

### Décision clé
- Nom fixé par le plan : `docs/analyses/2026-10-06-session-neuve-mesures.md`, quelle que soit la date
  d'exécution (l'en-tête dit la date réelle).
- Contenu : en-tête (plan, branche, base, décision, moteur), « Ce que ça change, en clair » (registre
  « Écrire pour qui décide »), puis une section par mesure **dans l'ordre P, R, M, E, W1, W2, A, K,
  Report** : critère cité mot pour mot, protocole exécuté, lignes citées, commande qui reproduit,
  verdict. Puis « Réfuté », « Voie retenue » (ce que les verdicts permettent : pastille retirée du repli
  Desktop si P, M, E, W1 ou W2, et A sont positifs ; sinon quel réglage manque, nommé), « Gestes
  humains » (le réglage préalable compté à part, puis la cible 0 contre le relevé), « Défauts
  relevés » (dont : `autoMode` du `.claude/settings.json` du dépôt lettre morte, la doc le dit ignoré
  dans les settings de projet ; `SKILL.md` de tâches laissés par `delete_scheduled_task`).
- **Report — mécanisme** (index temporaire : l'arbre de travail et la branche ne bougent pas) :

  ```bash
  F=docs/analyses/2026-10-06-session-neuve-mesures.md
  git fetch origin
  export GIT_INDEX_FILE="$(mktemp)"
  git read-tree origin/main
  git update-index --add --cacheinfo "100644,$(git hash-object -w "$F"),$F"
  ARBRE=$(git write-tree)
  C=$(git commit-tree "$ARBRE" -p origin/main -m "docs(preuve): mesures de la session neuve (P15)" -m "Plan: P15/S6/T9")
  unset GIT_INDEX_FILE
  git push origin "$C:refs/heads/main"
  ```

  Puis `git fetch origin` et `git diff --name-only origin/main~1 origin/main` → le seul `$F`.
- **Report en deux temps** : le premier push porte la section « Report » avec le protocole et
  `**Report :** à constater` ; une fois le push constaté (ou refusé), la ligne devient
  `**Report :** <positif|négatif : motif cité>` et un second report, même mécanisme, la pose (message
  `docs(preuve): mesures P15, verdict du report`). Critère, cité mot pour mot : Positif : « le fichier
  de mesures est committé et poussé sur `main` par la session prévue, sans refus » ; Négatif : « refus
  du classificateur ». Un refus d'une autre source (hook `pretooluse-git`, réseau) se cite tel quel et
  rend « négatif : <source> ».
- Report refusé → le fichier reste sur la branche, le Bilan donne à l'utilisateur la commande exacte
  (le bloc ci-dessus), compté comme geste.
