## T3 — La skill devient une procédure ; le narratif devient une décision

### Objectif

Réécrire `skills/executer-vague/SKILL.md` autour de l'option C, ≤ 250 lignes, et déplacer tout le
narratif historique dans `docs/decisions/2026-08-25-lecons-orchestration.md` (nouveau).

### Décision clé

Une skill est une **procédure** relue à chaque orchestration ; le *pourquoi* (« constaté sur MYO
le… », « leçon du 2026-08-23 », « trois pièges que ce code évite ») appartient à `docs/decisions/`
et ne doit plus être payé à chaque exécution. L'option C fixe la structure : voie normale =
sous-agent pour TOUTES les sessions ; voie headless = uniquement les sessions dont l'index déclare
`Env. = headless` (avec sa justification) ; pastille = repli hors Desktop. Le verdict = commits
(renvoi §4b/§5b) ; le lecteur JSON se réduit à l'extraction du **motif** (~30 lignes) — plus de
verdict PANNE élaboré, plus de fail-closed à trois branches : un JSON illisible est un motif absent,
les commits jugent.

### Lire / Modifier

- Créer : `docs/decisions/2026-08-25-lecons-orchestration.md` — les leçons extraites, datées,
  chacune en 2-4 lignes avec sa source (quel incident, quel jour). Y transférer notamment :
  l'arrêt-au-FAIL structurel, les pièges du lecteur JSON (tabulations, contenu-vs-chemin), la
  panne « verdict perdu en route », le worktree par défaut de la pastille, le trust indexé sur la
